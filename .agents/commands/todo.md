把下面这条问题记录到项目根目录的 `TODO.md`，只做记录，不做调研。

待记录内容：$ARGUMENTS
（若上面为空，取本次会话中最近讨论、且尚未记入 TODO.md 的那个问题。）

## 要求

1. **不要检索代码**：不读源码、不跑命令、不分析根因。只有用户已给出文件路径或代码位置时才照抄进去。
2. 先读一遍 `TODO.md` 保持格式：条目为 `## <类型> · <标题>`，条目之间用单独一行的 `---` 分隔。
3. 类型从 `BUG` / `待查` / `需求` 三选一，拿不准就写「待办」。不要臆测优先级。
4. 正文只写两小段，中文、简洁：
   - **现象**：用户描述的问题或诉求。
   - **待办**：要做的事；没定就写「待确认」。
5. 追加到文件末尾 footer 行（`（其余项见 README…）`）之前，footer 保持最底部。
6. 不改动其它条目，不执行 `git commit`。
7. 完成后只回报记了哪一条（标题），不复述全文。
