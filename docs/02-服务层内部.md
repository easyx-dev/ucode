# 02 服务层内部

> 服务层 = `@ucode/service`：**它是产品的调度中心**。pi 是**库**（进程内嵌入），不是进程；
> 服务层自己持有状态（SQLite + pi 兼容的会话文件），对控制层的壳只暴露协议接口。
> 仓库组织、磁盘布局、存储分治见 [01 实现设计](01-实现设计.md)。

## 一、装配与生命周期

`createService(config)` 打开服务存储、装配会话运行时、闸门与交互中转，返回一个
`Service`（= `CoreServer` + 生命周期方法）。传输由宿主（CLI）决定：

```
createService ─┬─ transport/rpc（unix socket）  ← 壳的首选通路
               ├─ transport/http（+SSE，兼发 Web 静态资源）← 浏览器
               ├─ transport/ws                 ← 需要单连接多路复用时
               └─ transport/stdio              ← 嵌入式（父进程 spawn）
```

- **单实例**：一个数据根一个服务，由 `host/registry.ts` 的实例锁 + SQLite 写锁保证；
- **判活**：注册表 + pid + 端点探测三重确认，任一不过都当"没有服务"（`kill -9` 的残骸必须能被
  自动清理，否则这个数据根再也起不来）；
- **优雅退出**：关传输 → 关会话运行时 → 清注册表 → 放锁；SSE 必须 `closeAllConnections()`（I-4）。

## 二、会话运行时（`session/`）

`SessionRuntime` 为每个会话装一台 pi 运行时：`DefaultResourceLoader`（cwd + **pi 目录**为 agentDir）
+ 一组**每会话扩展工厂**（工具闸门、记忆、子智能体、目标、回滚、Wiki、SSH、导入、钩子）
+ `createAgentSession`（`SessionManager.inMemory`）。

三条不变量：

1. **先落盘再广播**：基座的 `entry_appended` 在正常对话路径不触发（I-2），因此每次事件后比对
   内存态记录、把新增的追加进**会话文件**（`<pi>/sessions/*.jsonl`），成功后才广播 `entry_appended`；
2. **游标 = 行号**：断线续传按 `fromSeq` 补齐；检测到文件被整体替换（迁移/截断）时发 `resync_required`，
   让控制层重新全量同步；
3. **`root` 与 `piDir` 分开传**：业务模块拿数据根（自己推导 service/pi 路径），pi 相关的东西
   （agentDir / models.json / settings.json / trust.json）拿 pi 目录（I-26）。

多端同看同写：`prompt` 在会话正在跑时**排队进下一轮**（不拒绝），队列条数随 `status` 事件广播给
该会话的所有 attachment。

## 三、能力与闸门（`capability/`）

- **信任矩阵**：`implicit` / `local` → 全部能力；`untrusted` → 只读 + 对话。信任级别由传输声明。
- **工具闸门**（`tool-gate.ts`）：任何通路的工具执行都要过"信任矩阵 + 自主级别"，批准权归交互中转；
  **"本会话内总是允许"必须真的生效**（I-20）。
- **只读档是结构性的**（I-21）：`plan` 档把改动类工具从工具集里摘掉（模型根本看不到），
  命令类工具保留并由只读白名单逐条判定（`read-only-command.ts`）。
- **项目信任**（`project-trust.ts`）：默认拒绝加载项目本地资源，授信记录在 `<pi>/trust.json`（I-19）。

## 四、交互中转（`interaction/`）

`UiBroker` 承载人与 agent 的往返：阻塞式提问 / 批准、通知式消息、广播路由与去重、超时与降级策略。

- **降级而非挂起**：没有任何 attachment 能承载交互时，不把整轮挂死——请求落盘为**待决交互**，
  同时按策略拒绝当前这轮工具调用；超时/无人承载时给 agent 追一条"按最佳判断继续"；
- **首个应答生效**：同一请求广播到多个壳，第一个应答决定结果，其余自动作废；
- **持久化待决**：待决交互写进会话记录（`ui.pending`），重启后仍可应答（`ui.resolved` 收尾）。

## 五、存储（`storage/`）

```
会话正文：<pi>/sessions/--<escaped cwd>--/<时间戳>_<id>.jsonl   追加式，游标 = 行号
索引与元数据：SQLite sessions / interactions / service_meta      派生 + 事务
```

- `session-file.ts`：单会话读写（追加、读、修尾、检测整体替换）；
- `session-index.ts`：SQLite 索引与扫描（`sessions` 表 + `service_meta` 里的目录水位）；
- `store.ts`：门面 `createServiceStore`，把"会话仓库 + 索引 + 守卫"收成一个对象；
- `atomic.ts`：非追加写必须"临时文件 + fsync + rename"；
- `guards.ts` / `naming.ts`：路径安全与命名（会话 id、桶目录、文件名与 pi 完全一致）。

**密钥永不入库**：供应商密钥只写 `<pi>/models.json` / `auth.json`；协议层的回读形状里只有
`hasApiKey`。

## 六、业务模块（`modules/`）

一个模块可以贡献三张脸：**agent 面**（pi 工具 / MCP / 斜杠命令 / 子智能体）、
**服务面**（协议 C 命令 + 事件 + 通道）、**存储面**（SQLite 表或服务目录下的文件）。
装配在 `modules/registry.ts` 一张表里完成——新增功能不再同时改多个文件。

| 模块 | 说明 |
|---|---|
| `memory` | 项目级持久记忆（工具 + 文件） |
| `tasks` | 定时 / 闲时任务与调度器（命令 + 存储 + 常驻调度） |
| `hooks` | 生命周期钩子（只从服务目录读配置，绝不读项目本地 hooks） |
| `subagents` | 子智能体：继承闸门、不挂记忆与子智能体工具（防递归）、`maxTurns` 护栏 |
| `goal` | 目标模式：自动续跑与额度护栏（与 `plan` 互斥） |
| `undo` | 按轮回滚文件改动 |
| `wiki` | 项目知识库（读取必须过过滤：依赖/产物/敏感/二进制/超大/符号链接） |
| `ssh` | 远端执行：注册表不存密钥，argv 单参传递，`BatchMode=yes` |
| `import` | 从别的 agent 布局导入命令 / 技能 / 子智能体定义 |
| `marketplace` | pi 包市场：登记源、读目录、安装/卸载（装进 pi 目录即成为能力） |
| `insights` | 用量统计、支持包导出（脱敏）、迁移预检与应用 |
| `question` | 把"问用户"做成工具：接交互中转；超时/无人承载时明确报错并让模型按最佳判断继续 |
| `mcp` | 自建 MCP 桥：`<服务目录>/mcp.json` → stdio 服务器 → `mcp__<服务器>__<工具>`，会话结束关进程 |
| `plugins` | 服务目录下已装资源（extensions / skills / prompts / themes）的发现与汇报 |
