## 一、产品定位

ucode 是**基于 pi 构建的分层智能体**：核心层是 headless 的智能体本体，控制层是它的各种壳子，数据层是一台机器上的一个目录。它把 pi 的 agent loop 与扩展生态当作基座，在此之上补齐**多壳接入、多实例共享、远程控制与组织纳管**。

三条定位：

1. **数据层是一个目录**（默认 `~/.ucode`），而非数据库。可被任何语言独立实现、可 grep、可备份、可随目录整体迁移。
2. **核心层与传输解耦**。新增一种绑定或一种壳子不改核心层。
3. **能力走工具层，协议保持窄**。新增能力一律以工具/MCP 形式接入，不往核心协议里加消息。

与 pi 的关系：**定位为 pi 的一个宿主**，数据层格式做成 **pi agent-dir 布局的超集**，因此 `PI_CODING_AGENT_DIR=~/.ucode` 即可让 pi 及其生态直接读写数据层。【已决】

命名口径：**产品名、数据层目录名、logo 等属"品牌配置"（brand profile），是构建期注入的单一事实来源，不在代码里硬编码**。上游默认：项目名 `ucode`，数据层路径 `~/.ucode`（可被 `--data-dir` / 环境变量覆盖），中继服务 `uhub`（中文「枢纽」）。B 端定制 = 换一份品牌配置与资源、重新构建。

## 二、目标用户

**主线是个人开发者本地使用**；企业 B 端及企业级能力（统一纳管、跨网接入、审计）属后续。

| 用户 | 主要诉求 | 对应场景 |
|---|---|---|
| **个人开发者** | 本地开箱即用；多设备查看与接管；把活派到别的机器 | S-1、S-2、S-4、S-5 |
| **企业 B 端** | 统一纳管；免配置模型；跨网接入；审计与撤销 | S-3、S-6、S-7 |

## 三、核心场景

| 编号 | 场景 | 说明 |
|---|---|---|
| **S-1** | 本地单机编码 | 安装 → 启动 → 对话。核心层只监听本机，模型端点自行配置。 |
| **S-2** | 多设备协同 | 手机与桌面连的是同一个核心层、同一份数据层，状态本就同步；同一会话可在多处同时查看，交互请求两端都显示。 |
| **S-3** | 无人值守与定时任务 | 没有客户端在等时，会话仍持续运行；一条权限请求可延后应答，会话进入等待态并释放资源，重启后待决请求仍在。 |
| **S-4** | AI SSH | 把活派到另一台机器：目标机**不安装任何 ucode 组件**，经已登记的 SSH 连接执行远端命令。 |
| **S-5** | 远控 | 桌面壳探测目标机是否已装核心层，没有则安装，必要时做端口映射，然后用标准协议接入。 |
| **S-6** | 组织纳管 | 登录 uhub 获得能力集（模型端点、企业知识库、内部数据服务）与中继通路，实现异网远程控制。 |
| **S-7** | 项目级协作 | 仓库内放声明式配置，跟着仓库走；共享的是"关"而非"开"。 |

## 四、非目标

| 不做 | 理由 |
|---|---|
| 跨机集中数据层 | 数据层是 per-host 不变量，会话数据留在各 host。【已决】 |
| 多租户数据模型 | 数据层仍是单用户目录模型；新增的只是访问路径上的授权层。 |
| 插件隔离与插件市场 | 本地安装的插件，其信任等于文件系统所有权，隔离是假边界；分发复用 pi packages。 |
| 扫码配对 | 被 uhub 登录（身份 + 授权 + 中继）取代。 |
| Bot Channel（微信/飞书等） | 不在本产品范围。 |
| P2P 打洞 | 纯优化非功能；为一小部分连接引入一整套机制与一条新传输，性价比不成立。 |
| 端到端加密 | 暂不考虑；但保留「uhub 只按通道转发不透明字节、不解析核心协议」这条约束，以保住将来加它的可能性。 |
| 强制模式（强制登录） | 首发不做；实现路径已明确（模型配置只允许 uhub 来源），写入手册。 |
| TLS | 首发仅监听 loopback，不做 TLS；远程场景由 uhub 承担认证并启用 TLS。**远程能力进入后续版本时 TLS 变为必做。** |
| 第三方开发者生态 | 暂不开放：不对外提供正式 API/SDK/兼容承诺，协议 C 保持内部。【已决】 |
| 发布到公共包仓库 | 暂不发布，命名与版本策略暂缓。【已决】 |

## 八、变更追踪

本文集是 ucode 的**定稿架构**（基线 tag `spec-baseline`）。

**内容分两级**：**已决**（改动需记录）与 **【实现级】**（具体格式、清单、分帧、包内划分，可直接替换）。分级的目的不是拦住改动，而是**保持变更记录的信噪比**。

**机械保证**：此后 `git diff spec-baseline..HEAD -- docs/spec` 即是完整变更集。人工记录解释"为什么"，diff 保证"不漏"。
