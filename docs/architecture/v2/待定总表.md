### 归零不等于无事可做

**待定项缺的是"输入"，它们都拿到了。但另外两类工作仍然存在：**

1. **技术假设待验证（4 条，`v1/06`）** —— pi 的 session JSONL 是否严格只追加、`sessionManager` 能否覆写、pi 是否容忍未知文件、pi extension 运行时能否嵌入。**它们缺的是"事实"而不是"输入"，且验证结论会推翻 v1 的具体章节。** 这是当前最大的剩余风险，也是 v1 冻结前应当完成的最后一步
2. **实现级设计（大量）** —— 命令清单、消息形状、分帧、包内划分、uhub 的准入表怎么配、审计字段具体记什么。它们不需要架构决策，是开工后的常规设计工作

| **Q-2** 项目级作用域能否携带可执行内容 | **不携带**（已决）。项目级**只减不增**：能关（关闭能力，声明式无风险），不能开（Hook / 命令 / 自动连接的外部服务一律不行——那是「以你的身份运行他人的代码」）。团队共享 MCP 的需求改用组织级分发解决 | 01 §5.5 |
| **Q-5** 凭据失效通知机制 + uhub 侧准入与撤销 | **关闭**——不需要通知机制。通道断了就在中继时返回「通道已断开」；封禁 / 冻结 / 撤销都是**让通道不可用**，是同一个动作的两面。通道不可用是**普通运行时错误，不是状态变更**，agent 不需要「得知」。剩下的准入表怎么配属于 uhub 侧策略设计，无架构未知 | uhub §3.6 |
| **Q-4** uhub 身份载荷形态 + 审计字段 | **已关闭，问题被前提解掉**。项目方定：多个 attachment **连的是同一个服务层、同一个数据层，它们是同步的**——所以权限请求**在两端都显示**（广播、先答生效），不做"发到某台设备"的路由。因此身份载荷的形态只是"哪个身份"（授权需要），"哪台设备"不参与路由、可记入审计。审计字段的设计随之降为实现级工作，不是待定的架构决策 | v1 04 §五（已改为广播） |
| **Q-6** 能力目录与开关的形态与归属 | **已关闭**。项目方定：**可以在项目中显式关闭这些能力**（关闭知识库、关闭 MCP 等）。形态建议仍以 MCP 声明下发，但不再有待定项 | uhub §2.5 |
| **Q-3** 路径优先级的完整次序 | **问题不成立，撤销**。原先把"远控隧道"与"uhub 中继"当成两条并列的路去排优先级——**这与 uhub §4.4 已定的"远控是纳管动作、中继是常态通路"自相矛盾**。中继就是在远程操作服务层，web 能做什么它就能做什么，**不是需要规避的次等路径**。剩余的"环回 > 局域网直连"是显然的，不需要作为待定项 | 01 §7.4（已改正） |

## 不属于本表的另一类未定
