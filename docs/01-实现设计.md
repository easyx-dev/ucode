# 00 实现设计

> 本文是**工程实现设计**：仓库怎么组织、每个包负责什么、数据落在哪、怎么跑与怎么验。
> 架构的历史基线（重构前的定稿需求与 ADR）在 `docs/archive/`；本文与它冲突时**以本文与代码为准**。
> **改代码前先读文末「落地记录」**——那里是与 pi 基座、Node 运行时、打包形态打交道时踩出来的
> 反直觉约束（I-n）。

## 一、仓库组织

pnpm workspaces 单仓多包，依赖方向严格单向（`tools/boundaries.json` 是唯一事实来源）：

```
apps/web ─▶ @ucode/ui ─▶ @ucode/sdk ─▶ @ucode/protocol
apps/desktop ─(spawn CLI + 加载服务端点的界面)─▶ @ucode/branding
apps/tui ─────────────────────────▶ @ucode/sdk ─▶ @ucode/protocol
apps/cli ─▶ @ucode/service（宿主与 ensure）、@ucode/sdk、@ucode/branding、@ucode/protocol
@ucode/service ─▶ @ucode/protocol、@ucode/branding
```

| 包 | 职责 | 关键约束 |
|---|---|---|
| `@ucode/protocol` | 线契约：命令 / 事件 / 交互 / 通道 + 能力与信任类型 | 叶子；壳与服务端共享，**不得依赖 service/sdk** |
| `@ucode/branding` | 品牌参数与产物路径名 | 叶子；主入口必须浏览器安全（Node 推导走 `@ucode/branding/node`，I-18） |
| `@ucode/service` | 服务层：宿主 · 传输 · 会话 · 闸门 · 交互 · 配置 · 通道 · 存储 · 业务模块 | 唯一后端；不含任何控制层代码 |
| `@ucode/sdk` | 控制层 SDK：建连、命令封装、事件折叠、续传、四种传输的**客户端一侧** | headless：不 import ui、不假设 DOM |
| `@ucode/ui` | React 组件与视图模型 | 只被 web 复用（桌面加载同一份 Web 产物） |

壳（`apps/*`）都是**客户端**：渲染 + 输入 + 宿主差异。**没有一个壳 import `@ucode/service`**
（反向验收会断言这一点）；桌面壳更进一步——它连界面都从服务端点加载，自己只有主进程与 preload。

## 二、服务层内部

```
packages/service/src/
├── paths.ts        磁盘布局的唯一事实来源
├── service.ts      createService()：装配全部子系统，返回 Service（协议 C 的服务端）
├── types.ts        对外契约：Service / ServiceConfig / AttachmentView / ServiceBus
├── handshake.ts    hello → welcome：版本双校验、能力授予、会话摘要与续传应答
├── host/           实例锁 · 注册表与发现 · 端点探测 · 后台拉起与 ensure · 日志
├── transport/      stdio（嵌入式）· rpc（unix socket / tcp）· http（+SSE，兼发 Web 静态资源）· ws
├── session/        会话运行时：pi 装机器、多会话、事件扇出、游标续传、队列、差异落盘
├── capability/     信任矩阵 · 能力授予 · 自主级别 · 工具闸门 · 只读命令白名单 · 项目信任
├── interaction/    交互中转（ui-broker）：提问与批准、广播路由、去重、超时降级、持久化待决
├── config/         供应商与模型配置（读写 pi 目录的 models.json / settings.json）
├── channels/       通道实现：workspace（文件树 / git / 读取）与 pty
├── storage/        会话正文（JSONL）+ 索引与元数据（SQLite）
└── modules/        业务模块（一个域一个目录）+ 注册表
```

**业务模块契约**：一个模块可以贡献三张脸——① **agent 面**（pi 工具 / MCP / 斜杠命令 / 子智能体，
走 `(pi: ExtensionAPI) => void`）② **服务面**（协议 C 命令 + 事件 + 通道）③ **存储面**（SQLite 表）。
装配集中在 `modules/registry.ts` 一张表里，新增功能不再同时改多个文件。

| 模块 | 主要形态 |
|---|---|
| `memory` `tasks` `hooks` `wiki` | agent 面 + 存储面 |
| `subagents` `goal` `undo` `plugins` | agent 面 |
| `question` | agent 面：把"问用户"做成工具（接交互中转，超时/无人承载时明确报错） |
| `mcp` | agent 面：自建 MCP 桥（`mcp.json` → stdio 服务器 → `mcp__<服务器>__<工具>`） |
| `ssh` `import` `marketplace` `insights` | 服务面 + 存储面（各自带 agent 面工具或命令） |

## 三、磁盘布局

```
<数据根>/                      UCODE_DATA_DIR；默认家目录下的品牌数据目录
├── runtime/                   活句柄与本次运行的日志：不迁移、不进支持包、可随时删
│   ├── service.json            注册表（pid / serviceId / 端点 / 数据格式版本）
│   ├── service.lock            实例锁：一个数据根一个服务
│   ├── socket.sock             unix socket（路径过长则省略，退回只用环回 HTTP）
│   └── service.log             detached 进程的 stdout/stderr
└── v1/                        数据格式版本根
    ├── service/
    │   ├── service.db          SQLite（WAL）
    │   ├── cache/              可重建的派生缓存
    │   ├── memories/ tasks/ wiki/        尚未入库的功能域文件
    │   └── hooks.json ssh.json marketplaces.json nodes.json
    └── pi/                    pi agent-dir（pi 生态按这些名字认）
        ├── settings.json models.json auth.json   ← 密钥只落文件，永不入库
        ├── AGENTS.md trust.json
        ├── extensions/ skills/ prompts/ themes/ agents/
        ├── sessions/          会话正文 JSONL：追加式，游标 = 行号
        └── npm/               运行期安装的 pi 包
```

`v1` 是**数据格式版本**，不是产品版本；格式演进时新旧目录并列，迁移是"读旧写新"而不是原地重写。
`runtime/` 放在数据根里、版本目录外：隔离由版本边界承担，运行时状态因此跟着数据根走
（`UCODE_DATA_DIR` 一个变量管全部，测试天然隔离）。

## 四、存储分治

| 数据 | 位置 |
|---|---|
| 会话正文（entry 流） | `<pi>/sessions/*.jsonl`（追加式，游标 = 行号） |
| 会话索引与元数据（名称、归档、条目数、更新时间） | SQLite `sessions` |
| 待决交互与审批记录 | SQLite `interactions` |
| 服务元信息与索引水位 | SQLite `service_meta` |
| 任务 / 记忆 / 钩子 / 市场 / 节点 / 信任记录 | 当前是文件，随模块迁入 SQLite 时按序追加迁移 |
| 供应商与模型配置、密钥 | `<pi>/{models.json,auth.json}`——**密钥永不入库** |
| skills / prompts / themes / extensions / 已装 pi 包 | `<pi>/**` |

规则：**需要查询、聚合、事务、跨会话引用的结构化状态进 SQLite；模型要直接读写、人类要能 diff、
或 pi 生态要识别的资源留在 pi 目录。**

索引始终是**派生数据**：真相是扫描会话目录本身，`refreshIndexIfStale` 用"文件数 + 最新 mtime"
做轻量判据，变了就重扫（用户可能用真正的 pi CLI 往同一目录里写会话）。

## 五、运行方式

| 场景 | 命令 |
|---|---|
| 常驻服务（唯一后端） | `ucode service start`（detach）/ `--foreground`（前台） |
| 嵌入式（父进程 spawn 的壳） | `ucode service start --foreground --stdio`：不写注册表、不占实例锁、不开端口 |
| Web / TUI 壳 | `ucode web` / `ucode tui`（发现服务 → 没有就拉起 → 连上） |
| 管理 | `ucode service status\|stop\|logs -f`、`provider add\|list`、`node add\|list\|remove`、`trust` |

壳与服务的关系是**多点对一点**：多个壳连同一个服务，一个会话的多个 attachment 同看同写。

## 六、构建与测试

- **dev 态不构建**：`exports` 的 `dev-src` 条件指向 `src/*.ts`，Node 原生类型剥离直跑源码；
  安装/发布形态走 `dist/*.js`（`pnpm build:libs`）。条件必须写成 `{"types","dev-src","default"}`（I-10）。
- **测试直跑源码**：`vitest` 的 `resolve.conditions` 与 `ssr.resolve.conditions` 都要配 `dev-src`（I-11）；
  spawn 子进程必须显式带 `--conditions=dev-src`。
- **服务层测试**用录制式假供应商（`service/src/testing/fake-provider.ts`）+ 共享 harness
  （`service/src/testing/service-harness.ts`），确定性、零成本、不依赖网络。
- **两条验收**：`tools/acceptance-service-standalone.ts`（独立安装跑通一轮对话）、
  `tools/acceptance-reverse.ts`（壳的生产依赖树不含 `@ucode/service`）。
- **门禁**：`pnpm check` = typecheck + Biome + 依赖边界 + 品牌字面量 + 全量测试；
  门禁自身由 `tests/gates.test.ts` 自证会拦人。

## 七、落地记录（I-n）

**与 pi 基座**

| # | 约束 | 处置 |
|---|---|---|
| I-2 | 基座的 `entry_appended` 在正常对话路径不触发 | 会话运行时**按差异落盘**：每次事件后比对内存态记录、把新增的追加进会话文件，**成功后才广播**（"先落盘再广播"由我们自己的顺序保证） |
| I-12 | 与内置供应商同名的 id 会被基座合并模型目录 | `provider.add` 写入后回读并报告"声明 vs 解析"的差异；`pickModel` 优先用户自配的供应商 |
| I-19 | 项目本地资源默认**会被加载**（`projectTrusted` 默认为真） | 构造 `DefaultResourceLoader` 时显式过信任门，**默认拒绝**；授信记录在 `<pi>/trust.json`，出口是 CLI 的 `trust`。验收方式是把"一被加载就写标记文件"的探针扩展放进去，断言它没跑 / 授信后才跑 |
| I-20 | "本会话内总是允许"曾经是死选项 | `tool-gate` 必须真的读 `sessionAllowed`；用"第二次不再弹窗"的测试锁住 |
| I-21 | 只读档要改工具集，不能只拦调用 | `plan` 档用 `setActiveToolsByName` 把改动类工具摘掉；判据取假供应商收到的 `tools`（证"模型真的看不到"） |

**与存储**

| # | 约束 | 处置 |
|---|---|---|
| I-22 | pi 的 `SessionManager` 全程内存态（我们用的是 `inMemory`），**会话正文由服务写** | 服务以 **pi 兼容的 JSONL** 写 `<pi>/sessions/`：追加式、游标 = 行号、header 定义会话；因此真 `pi` CLI 指向同一目录即可直接读写 |
| I-23 | 索引是派生数据，且目录可能被别的进程写 | SQLite 索引 + "文件数 + 最新 mtime"水位：变了就重扫；索引损坏重扫即可，不是数据事故 |
| I-24 | 一个数据根只能有一个服务 | `runtime/service.lock`（`wx` + 内容原子写入 + 持有者 pid + 启动宽限期）+ SQLite 写锁；判活是**注册表 + pid + 端点探测**三重确认，任一不过都当没有服务 |

**与 Node / 打包**

| # | 约束 | 处置 |
|---|---|---|
| I-1 | Node 的原生类型剥离**不支持 JSX** | 被 Node 直接执行的包（`service` / `sdk` / `apps/cli` / `apps/tui`）只用 `.ts` + `createElement` |
| I-25 | `node:sqlite` 是实验特性，且 Node 22 需要 `--experimental-sqlite` | `engines` 抬到 **≥ 24**（免 flag）；拉起常驻服务时带 `--disable-warning=ExperimentalWarning` 抑制启动噪音 |
| I-10 | `exports` 条件按出现顺序取第一个匹配，`default` 永远匹配 | 一律写成 `{"types","dev-src","default"}` |
| I-11 | 测试里的 `@ucode/*` 走 SSR 运行时解析 | 同时配 `resolve.conditions` 与 `ssr.resolve.conditions`；spawn 子进程显式带 `--conditions=dev-src` |
| I-4 | SSE 是长连接，**心跳定时器也会拖住退出** | 两处都要处理：① 优雅退出时 `closeAllConnections()`（否则 `server.close()` 一直等连接自己结束）；② 心跳等待**不能**用 `stream.sleep()`——它的定时器不受我们控制，关流后仍然活着，SIGTERM 之后事件循环被挂住、`service stop` 耗尽超时（重构后实测复现，现改为自管定时器 + 关流时叫醒）。回归测试：`tests/service.test.ts` 的"带 SSE 订阅者时也能优雅退出" |
| I-9 | 打包桌面壳 = 三层产物（主进程 / preload / 渲染进程 + 服务层单文件 bundle） | esbuild 输出必须 esm（cjs 会因基座顶层 await 失败）；基座 / ws / jiti 保持 external |
| I-7 | Electron 主进程与 preload 不能有 TS 语法 | 主进程 `.mjs`；preload 必须是 CommonJS（沙箱 `require` 只认 electron 与少数内置模块） |
| I-18 | `branding` 主入口必须浏览器安全 | Node 专有推导走 `@ucode/branding/node` |

**与控制层**

| # | 约束 | 处置 |
|---|---|---|
| I-5 | 前端选择器不能返回新建的数组/对象 | 派生数据在组件里用 `useMemo` 算，否则 React 无限重渲（整页白屏） |
| I-6 | 壳只依赖 `sdk` | 传输做成 sdk 子路径（`@ucode/sdk/http` 等）；服务端那一半在 `service/src/transport/`，两侧只共享 `protocol` 的消息 schema |
| I-13 | pi-tui 的 `Editor` 不会替调用方清空输入框 | 提交回调里自己 `setText("")` |
| I-14 | `toDisplayItems` 已经把流式尾巴算进去了 | 视图层不要再拼一遍流式文本，否则出现两段一样的回答 |
| I-15 | `web` 子命令服务的是构建产物，不是源码 | 改完 `apps/web` / `packages/ui` 必须 `pnpm -F @ucode/web build` |
| I-16 | 多端协作靠"一个服务 + 多个客户端" | 壳各自拉起后端会互抢写权限、留下孤儿进程；现在壳 `ensureService`（发现 → 连上，没有就拉起） |
| I-17 | 运行时状态不进数据目录，判活要三重确认 | 注册表 / 锁 / socket / 日志都在 `<数据根>/runtime/`：放进数据目录会被迁移与支持包带走 |

**本仓自身的坑**

| # | 约束 | 处置 |
|---|---|---|
| I-26 | **`dataDir` 与 `piDir` 是两件事**（重构中真实踩到：把数据根当 pi 目录传给 `agentDir`，扩展与模型全都找不到） | `ServicePaths` 同时给出 `root` 与 `piDir`；**业务模块的参数一律是数据根**（内部用 `servicePaths()` 推导），**pi 相关参数一律是 `piDir`**（`agentDir` / `trust.json` / `models.json` / `settings.json`）；`SessionRuntimeOptions` 里两个字段同时存在，就是为了让这件事在类型上看得见 |
| I-3 | 依赖边界门禁用 Oxc 而不是 TS 编译器 API | TS 7 无 JS API，依赖它的工具会巡游 0 个模块、**门禁静默失效**（已实测：dependency-cruiser / typescript-eslint 系在 TS 源码上什么也不检查） |
| I-27 | **桌面壳加载服务同源的界面，不自己构建渲染进程** | 桌面窗口 `loadURL(<服务 http 端点>)`，跑的就是 Web 壳产物：没有 CORS、界面永远与 Web 一致。代价是**打包形态必须带上 Web 产物**（`core-bundle/web-assets`），否则服务发不出界面就白屏——主进程用 `--web-assets` 把位置告诉服务层。另：桌面渲染进程若从 `file://` 加载再跨源连服务，会撞 CORS；给服务放开 `Access-Control-Allow-Origin` 则是**安全回退**（任何网页都能读到本机会话），因此不做 |
| I-8 | Electron 二进制下载 | 默认源可能拉不动；`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 可手动补 |
