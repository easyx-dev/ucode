# 界面规格

各块界面怎么搭：分区、间距、层级与具体取值。通用规则（token、颜色、排版、圆角、阴影、动效、状态）见
[`DESIGN.md`](../DESIGN.md)，组件的结构与行为见 [`components.md`](./components.md)。

## 应用骨架

主区是三栏：侧栏 | 对话区 | 工作台，用 `base/resizable`（底层 `react-resizable-panels`）。
尺寸一律用**像素**（库把数字当像素、字符串当百分比），栏宽不随窗口缩放、也不随界面密度缩放
（默认值是 `utils/panel-layout.ts` 的像素常量，密度只改间距、控件高度与内容高度上限）。

| 位置 | 取法 |
| --- | --- |
| 侧栏 | 200–400，默认 288；**收起时不参与分栏**（用状态决定是否渲染面板，不用 CSS 隐藏） |
| 对话区 | 400–不设上限，占剩余；面板底是 `bg-surface`（配 `md:rounded-md` + `md:border`），四周留白由外壳容器统一留（`md:p-shell-inset`，面板自己不写 margin），栏与栏之间的间隙交给分隔条 |
| 工作台 | 400–不设上限，默认 640（展开时按窗口夹取）；与对话区同形的面板（`bg-surface` + `md:rounded-md` + `md:border`），四周留白同上 |
| 开关 | 侧栏按钮在最左、工作台按钮在对话区右上角，图标随状态切换 |
| 持久化 | 按栏记宽度（像素），键 `<slug>-panels-<组名>`；收起状态另记（`-sidebar-collapsed`、`-workbench-open`） |

- 分隔条**不画线**：栏与栏靠底色差分层。命中区就是栏间距——侧栏侧 12px（`-ml-3` 叠到侧栏右边缘留白上）、
  工作台侧 8px（`w-2 -ml-1`：命中区 8px，两栏卡片之间只留 `--shell-inset`）、工作台内部侧栏侧 6px（`-ml-1.5`），
  悬停只有 `cursor-col-resize`，键盘聚焦给 `focus-visible:bg-ring/40`。外侧边缘的间隙一律由外壳容器的
  `md:p-shell-inset` 留，分隔条只负责栏与栏之间（栏不参与分栏时分隔条一并消失，空隙由外壳垫出）。
- 需要可见分界时用**面板自己的边框**（如文件树列自带 `border-r`），不用分隔条。
- 恢复宽度用每个面板自己的 `defaultSize`，不用库的 `defaultLayout`（收起某栏后面板数会变，记忆会被忽略）。

窄屏（< 768）下三栏退化为抽屉，两个抽屉的底色不同：侧栏与会话列表是**浮层**，用外壳的玻璃面（`bg-glass`）；
工作台是**铺满屏幕的主面板**（不是浮在对话上的东西），用实色面板底（`SheetContent` 的 `surface` 开关）——
玻璃面压在内容之上会透出下层，看上去像半透明。

**侧栏项目行**（会话列表的项目分组）：组头是折叠开关兼拖拽把手（文件夹图标 + 项目名），右端只留两个
入口——**本组新建会话**与**更多操作**菜单（悬停才现，触屏常驻），宽度让给项目名（名称吃掉整行剩下的地方，
长了就地截断）。菜单里是重命名、项目记忆开关与**跟随全局默认**（最后这项只在项目显式设过记忆开关时出现——
点过之后就不受全局开关影响了，留一个回去的入口）。
未读汇总点在名称之后（收起时才出）。项目记忆的生效值是「项目显式设置 > 全局默认」：开着的项目（全局开着而项目
没设过也算开着），名称前的文件夹图标染成信息色（列表里唯一常驻的记忆标记），悬停整行给一条说明（顺带带上
目录——组头是拖拽把手，路径就是这一行的身份），触屏看不到悬停则靠图标本身。

**窗口标题**：标题由 `document.title` 驱动（web 的标签页、桌面端窗口）。工作区挂载期间它反映待处理状态，
优先级从高到低取一个：有会话在等用户 → `待审批 / 待回答 / 待确认 · <品牌标题>`（与服务端 `status` 同序，
取最先命中的那一类，不逐条累加）；否则有未读 → `(N) <品牌标题>`（`99+` 封顶，与侧栏的未读点同口径、
只算根会话）；两者都没有就是品牌标题原样。离开工作区（登录页 / 服务不可用）也还原成品牌标题。

**无标题栏窗口**（macOS 桌面端，`titleBarStyle: hiddenInset`，系统红绿灯已隐藏）：窗口控件由界面自绘——
三颗点（关 / 最小化 / 全屏）固定在左端，位置是我们定的，不跟任何系统灯位走，展开 / 收起侧栏都不移动：

| 状态 | 三颗点落在哪 | 让位方式 | 拖拽宿主（控件挂在它里面） |
| --- | --- | --- | --- |
| 侧栏展开 | 侧栏顶部空区 | 侧栏内容从 48px 开始 | 侧栏顶部那一条（0–48，宽度随分栏） |
| 侧栏收起 | 对话区头部左端 | 头部左内边距 80px | 对话区头部整行 |
| 设置 / 使用统计 | 面板左上角 | 面板内容从 48px 开始 | 不变（面板盖住的是内容，控件在最上层） |
| 服务不可用 | 窗口左上角 | — | 壳层自己渲染一块 |

要点：

- **控件必须是「覆盖它那条拖拽区」的后代**。`-webkit-app-region` 的 `no-drag` 只对**同一子树**生效：
  把控件挂成宿主拖拽区的兄弟子树，宿主就会吃掉它的点击（表现为「点一下只会拖窗口」）。
  布局因此收一个 `windowControls` 节点，而不是自己再铺一层覆盖图。
- 对话区头部在无标题栏窗口里**整行是拖拽区**（里面按钮由 `.window-drag button` 自动排除），
  展开与收起两种状态下拖拽手感一致。

- 三颗点的中线分两种情况，且展开 / 收起之外都不动：**展开**时它落在侧栏顶部空区，取「对话区头部那行的控件中线
  减去面板距窗口顶的间距」（点属窗口镶边，不该被面板的上留白推下去，那一段就是外壳容器 `p-shell-inset` 的顶边留白）；
  **收起**时它就在头部那一行里，
  直接取那行的控件中线。两个值都不写死：布局用 `ResizeObserver` 实测后写到 `<html>` 的
  `--window-controls-center`，壳层拖拽条用 `calc(中线 - 点高 / 2)` 定位——密度或字号变化时两边自动跟上，
  壳层不需要知道头部的任何几何。
- 顶部让位取 48px（`TITLE_BAR_INSET`）：比控件实际占的高出一截，密度 / 字号调大后控件下移几像素仍在其中。
  工作区的四周留白（外壳容器的 `md:p-shell-inset`）**保持原样**——让位的是侧栏与全屏面板，不是对话区与工作台。
- 控件的纵向位置**只由 `paddingTop` 决定**（容器不能用 `items-center`，那会在内边距之上再居中一次，把点往下推）；
  布局量中线时要跳开控件自己（控件容器带 `data-window-controls` 标记）——否则是自我引用，每次重算都会再漂一截。
- 中线变量的回退值是**顶部让位区的中间**（`TITLE_BAR_INSET / 2`）：设置 / 服务不可用这类没有工作区可量的屏幕就落在这里，
  而不是贴到窗口边上（变量由布局写入并在卸载时清掉，所以这两类屏幕读到的就是回退值）。
- 点尺寸固定（`size-window-control`，14px，不随字号密度缩放）、左起 20px、间距 8px、尾部 8px、
  横向共 86px（`WINDOW_CONTROLS_WIDTH`）。
- 交互按 macOS 交通灯的惯例：悬停整组时点内露出操作符号，窗口失焦时整组 `opacity-40`；
  窗口焦点与全屏态由主进程经 `desktop:window-state` 下发，标题条在失焦时也一次点得动（`acceptFirstMouse`）。
- 绿点是**全屏**：点它进 / 出全屏，符号与文案随状态换（全屏时是朝里的那对箭头）；**⌥ 点击是最大化 / 还原**
  （同一颗钮的 macOS 变体，AppKit 里它就叫 zoom button，动作 `zoom`；全屏期间不接 ⌥——全屏窗口不可缩放）。
  拖拽区双击也能最大化（系统标题栏双击），但那条路受系统「双击窗口标题栏」设置影响，只能算第二条路。
- 控件在最上层（`z-chrome`，见 DESIGN.md「层级」），弹层打开的遮罩盖不住它。
- 常量与判定在 `apps/desktop/src/shared/chrome.ts`，布局侧只收 `titleBarInset` / `windowControlsWidth`
  / `windowControls`（web 不传，即 0 / 不渲染，界面不留空）。拖拽区用共享样式里的 `.window-drag`
  （`-webkit-app-region: drag`，内部 `button` 自动排除拖动）。

## 交互嵌套

一行本身可点时用 `button`（或 Radix 触发器），**里面不能再放可交互元素**：需要第二个动作（如「点路径打开预览」）
就把动作做成同级按钮，让触发器的命中区缩到「图标 + 名称」那一截。按钮里套按钮会产生无效 HTML，读屏与键盘焦点都会错乱。

## 工作台面板

VSCode 式的「活动栏 + 侧栏 + 编辑器区」，窄屏把那 40px 宽的活动栏换成顶部的视图条；条状区高度与列表行高统一：

| 区域 | 取法 |
| --- | --- |
| 活动栏 | **仅桌面端**：宽 40px，`border-r border-border`，竖排图标按钮（`size-8`）：源代码管理 / 项目文件 / 终端（桌面端另有「浏览器」，见下），最下是收起面板 |
| 视图条 | **仅窄屏**：< 768 时它取代活动栏，压在列表页顶部——36px 一行，视图按钮（`h-7`，图标 + 文字，选中 `bg-state-selected`）+ 右端「收起面板」。装不下时按钮先截断文字（收缩到图标那一档宽），最右的收起按钮不会被挤走 |
| 侧栏 | 宽 180–360（默认 240）；顶部一行控件（根名 + 筛选 + 刷新 / 改动与历史切换 + 分支 + 刷新 / 终端的新建与刷新），行高 36、行内控件 28（筛选行桌面端 `h-7` 与下方的列表行同高；窄屏抬到 `h-8` 并保 16px 字号，不让 iOS 聚焦时缩放页面）；列表行高 28、`rounded-md`、选中 `bg-state-selected` |
| 标签条 | 高 36px（与对话区头部同档），`border-b border-border`；一份文档一格、溢出横滚；每格是「标题按钮 + 关闭按钮」两个同级元素；窄屏最左是返回列表，最右另给一个「收起面板」（抽屉没有别的退出口） |
| 编辑器区 | 占剩余宽度；内容自带 36px 工具条与滚动区；diff 用行号 + 增删底色 + 语法高亮（着色值走 `--code-*`，适配器见 `business/markdown/shiki-diff.ts`） |
| 终端 | 与其他文档同列的标签（图标 `SquareTerminal`，标题按它在侧栏列表里的序号）；字号取基准的 6/7（与 diff 行同档）、字体走 `--font-terminal`（默认与代码字体同源，可在设置里换成 Nerd Font 让提示符的图标有字形），配色由 `ITheme` 采样语义 token 给出（含 ANSI 十六色，随主题与深浅重算）；进程退出后保留最后一屏并在下方补一行「已结束（退出码 N）」 |
| 浏览器标签 | **仅桌面端**，载体是 Electron 的 `<webview>`（不是本地渲染的内容）：一条 36px 工具条（后退 / 前进 / 刷新 / 地址栏 / 元素选择 / 开发者工具）+ 一行标题状态 + 画面；工具条与标题行之外不套壳。**所有浏览器标签常驻**（切标签只切可见性、换工作目录也留着）——卸载 `<webview>` 等于销毁那个页面 |
| 空态 | 垂直居中：图标 `size-7 text-foreground-subtle` + 主文案 `text-sm font-medium` + 说明 `text-xs` |
| 分界 | 活动栏与侧栏各自用 `border-r` 画可见分界；侧栏与编辑器之间的分隔条不画线 |

- 目录行只用折角符（`ChevronRight` 转 90°），不叠文件夹图标；文件按类型给图标（`utils/file-icons.ts` 的映射），不引图标资源。
- 图标一律 `size-icon-sm text-foreground-subtle`。
- 文件树的 git 装饰：改过的文件名用状态色（`git-*`）并在右侧给字母徽标（`U` / `!` / `M` / `A` / `D` / `R`…），
  目录按「其下最重的那一个标记」着色、不加字母——颜色与字母都只表达状态。
- diff 默认双栏（并排）并记住选择（键 `<slug>-diff-mode`，另有 `<slug>-diff-wrap`）：横向溢出由编辑器内容区整块滚动，
  行与表格宽度跟随内容，底色不会在横向滚出来的区域断掉。渲染与配色由 `@git-diff-view/react` 提供，配色在
  `styles/third-party.css` 里整组改写成语义 token。
- 窄容器（< 30rem：移动端整屏、拖窄后的工作台）下统一模式的**两列行号收成一列**（有新号显新号、删除行回落旧号），
  列宽按库自己算给一列的那个值（`--diff-aside-width--`），而不是它默认的两列宽（还带 100px 下限，350px 的内容区里
  能占掉近 100px）。只收行号，展示方式与换行仍按用户偏好；规则在 `styles/third-party.css` 的 `@container diff` 里。
  同一阈值下 diff 工具条只剩图标：「统一 / 双栏」的文案与「改动」里的「N 个文件」收起（`base/diff-controls` 的
  具名容器 `diff-toolbar`，只对挂了它的那几行生效）；「自动换行 / 全部展开」本就是图标按钮。
- 「全部改动」把多个文件的 diff 堆叠成一份文档：每块带文件头（状态、路径、增删）与折角，块内容进入视口才取数。
- 改动列表覆盖 submodule：子模块内的改动按「子模块路径/文件」与主仓库的文件同列，分桶按子模块自己的 index 语义
  （它的「已暂存」就是它自己的暂存区），diff 与两侧原文都在子模块仓库里取；指针变更仍是 `子模块路径` 那一条，
  看的是主仓库记录的 commit 变化。两者折树时会落到同一个节点上，那种节点按目录渲染、展开后第一行才是它自己。
- 终端的标签与进程一一对应：关标签即结束终端，所以终端标签**不参与**「超限丢最早」（被挤掉会留下一个看不见的进程）；
  进程按工作目录归口并活在服务端，切会话时标签会清空、进程还在，侧栏列表里能重新打开（重挂时重放最近的输出）。
  终端不新增 ANSI 配色 token：十六色都由语义色或它们的混合派生，深浅色与配色主题换代时整组跟着走。
- 窄屏（< 768）抽屉铺满屏幕宽度，面板内退化成单列：侧栏与编辑器区互斥，打开文件即切到编辑器；
  两侧由 `sidebarVisible` **一个状态**决定——打开文档即收起侧栏、返回箭头即展开、点视图条里当前那个视图即收起
  （看编辑器）、点另一个即展开并切换；不要为此另立一份局部状态，否则视图条的按钮会点了没反应。
  顶部**只有一条 36px 的头**：列表页是视图条，看文档时是标签条（最左返回、最右收起）——不叠成两条；
  那 40px 宽的竖排活动栏只在桌面端出现。

## 消息区

对话流不是卡片列表，而是页面底色上的一列内容：分层靠留白、字号与颜色，不靠外框。
实现落位 `business/chat/chat-rows.ts`（扁平行投影）、`business/chat/message-row.tsx`（行渲染）、
`business/chat/message-list.tsx`（虚拟滚动）。

### 对话区头部

| 元素 | 取法 |
| --- | --- |
| 状态表达 | 头部**不铺底色**，状态只由顶缘一条 2px 的线（`h-0.5`，`-z-10` 的绝对层）表达：生成中是 `bg-foreground-subtlest` 的轨道 + 一段 `w-1/3 bg-foreground-subtle` 的短条从左扫到右（`animate-tone-sweep`，3s 一轮循环、线性；减弱动效偏好下短条整条收掉，只剩轨道底线）；等用户的两态**本身停着**，整条满色不动（`bg-warning` / `bg-destructive`）。生成中的两层取**文本弱色**而非 `primary`：`primary` 在暗色下是近白，持续扫动会刺眼；节奏也不宜快，取 3s。色调切换时 150ms 过渡颜色；优先级与服务端 `status` 同序（待审批 > 待表单 > 生成中），判定在 `business/chat/session-tone.ts` |
| 状态的可见表达 | 那条线只对看得见的人有效，故另给一行 `sr-only` 文案（生成中 / 等待你的输入 / 等待权限审批）；原先的「生成中」文字与转圈已去掉 |
| 右侧入口 | 依次是：用量徽标（有占用或有用量才出现）、复制会话记录（取 JSONL 文本，点了才取）、重建运行时、工作台开关 |
| 左侧 | 侧栏开关在最左、子会话返回键与「分叉自…」链接跟在标题后；无标题栏窗口里整行是拖拽区 |

| 元素 | 取法 |
| --- | --- |
| 行间距 | 行首用 padding：新一轮 `pt-6`、轮内 `pt-3`。**不能用 `space-y-*` / `mt-*`**——虚拟列表按元素高度测量，margin 不计入会让滚动位置算错 |
| 用户消息 | **反色气泡**：`bg-inverse` + `text-inverse-foreground`（深浅两模式都是深底浅字：浅色 `neutral-800` 底、深色压到 `neutral-700`）+ `rounded-lg rounded-br-xs`（右下收一档到最小档），右对齐，`max-w-[85%]`；不描边——反色面自身就是边界 |
| 用户消息目录条 | 该会话用户消息 > 1 条才出现，且只在**内容列两侧有留白**时：消息区（`@container`）窄于 59rem（每侧留白不足 24px）就整块收掉，不往内容上挤。位置取对话 header 的 `px-4`——贴对话区左侧，与内容列之间留出留白；每条用户消息一格、每格 12px 固定间距自上而下排成一条紧凑的刻度条（长会话装不下时整列等比收缩）、垂直居中；刻度 `h-0.5 w-4`（常态 `scale 0.5` = 8px），默认 `bg-foreground/20`、当前 `bg-foreground-subtle`；悬停那格变色（`bg-foreground`）变长（`scale 1.5` → 24px）、浮出这条消息的正文预览，**两侧邻居按距离递减地也拉长**（每远一格少 4px，四格之外回到常态；永远短于悬停那格），点击平滑滚到那一条 |
| 用户消息的 chip | 句子外的技能 / 命令排在气泡上方，句子里的 `@` 引用就地渲染；两类同一套外观（`rounded-xs` + `bg-muted` + `text-xs`），引用可点开工作台预览 |
| 图片 / 附件 | 正文里一律是带描边的等宽文字 token（`rounded-xs` + `border-border` + `bg-background` + `font-mono text-xs`，前带 `size-icon-xs` 类型图标），内容是 `图片<序号>` 与文件名；点开原图弹层或下载 |
| 工具产出的图片 | 工具卡展开体里直接铺图（`max-h-96` + 描边，点开放大到全屏，同正文图片）；正文被旧输出清理后图片仍在，下面补一行说明「已从模型上下文清理」 |
| 页面元素上下文 | 输入区里是一枚**芯片**（同上一行的描边与字号，但用 sans 不用 mono）：`MousePointer2` 图标 + 元素的可访问名（没有则「未命名元素」），悬停给出选择器与所在页面；整段摘要（标题/URL/选择器/位置/样式/属性/文本/附近/HTML 片段）**不进编辑器**，只在发送时落进消息正文（方言投影从节点 attrs 取） |
| 过长的用户消息 | 超过 `max-h-80` 折叠（`overflow-hidden`），下方给「展开 / 收起」入口 |
| assistant 正文 | 直接铺在面板底（`bg-surface`）上，不套容器；排版交给 `.md-content` |
| 思考过程 | 只在展开聚合行后出现，仍是单行灰字（「思考过程」+ 时长），再展开才看正文 |
| 工具行 | 单行 `h-8`：图标 + 标题 + 入参摘要；**不设底色**，悬停只让末尾的小三角现身；展开体缩进 `pl-6`，输出用 `bg-muted/50` |
| 聚合摘要 | 连续的思考与工具调用折成一句灰字：「思考了 3 次，使用了 2 个 Shell，1 个 打开页面」；无图标、无底色，悬停出小三角 |
| 改动卡片 | 一次写盘（编辑 / 写入）**独立成卡片**：与提问段同一套外观（`bg-muted/40` + 描边 + `rounded-lg`），里面就是那张工具卡（标题 + 路径 + 展开后的 diff），展示控件靠右、悬停卡片或展开时才现（常占位，不挤路径），失败 / 执行中仍在行尾出状态图标 |
| 提问段 | 一次提问与其答复**独立成段**：`bg-muted/40` + `ring-1 ring-border-strong` + `rounded-lg`，内部按「主题 / 问题 / 选项」排 |
| 审批记录段 | 与提问段同一套排版：结论行（允许为中性色、拒绝用 `text-destructive`，带盾形图标）+ 工具名与对象（`font-mono`） |
| 生成中提示 | 列表最后一行：`Spinner` + 「工作中」+ 本轮已走时长（`tabular-nums`，整数秒，与落定后页脚里的耗时同源）；悬停出浮层（tooltip）列本步明细：本次请求总耗时、等待模型响应 / 等待首帧 / 生成 / 执行 <工具> 四段、等用户那一行（正挂起时报「等待权限审批 / 等待你的回答」，等过了报「其中等用户」）、本轮总耗时。所有状态（在等什么、卡在哪个工具、在等谁）只在浮层里出现；取不到阶段（重连后重取快照）时浮层不出现，只剩行内那个数；按一秒刷新 |
| 轮页脚 | 模型 · 耗时，右侧是复制与分叉入口；**只在这一轮落定后才渲染** |
| 操作行 | 时刻 / 分叉 / 编辑 / 复制等悬停才现（触屏常驻），用 `min-h-6` 占位避免出现时顶动内容 |
| 浮起入口 | 「回到底部」这类按钮走浮层取法：`bg-popover` + `ring-1 ring-border-strong` |

- 可展开的行一律不设 hover 底色——密集的工具行会把底色连成一片灰带；可点靠悬停时才现的小三角表达。
- 行的 key 取 `ChatItem.uid`（跨「乐观条目 → 权威条目」不变），**不能取 `id`**：key 一变整行会被卸载重建。
- 连续的思考与工具调用合成一行摘要；正文 / 图片 / 附件按定义打断聚合。
- 写盘类工具（编辑 / 写入）自己成一张改动卡片、不并进聚合：聚合会把改动折进一句「使用了 2 个 编辑」，
  事后回看时看不出改了哪几行，而「改了什么」正是最常回看的内容。它们也不再计入摘要的次数。
- 改动卡片里的 diff 与 git 面板同源（`@git-diff-view/react`，渲染件 `business/markdown/patch-diff.tsx`）：
  未变更区域的折叠展开与语法高亮都归库（着色同代码块，见 `business/markdown/shiki-diff.ts`）；
  改动量超过编辑距离闸门时退化成「全删 + 全增」。整块高度照工具卡的惯例收在 `max-h-96` 内滚动。
- 卡片里不报行号：patch 由改动片段拼成，行号从 1 起、不是文件里的位置，当文件位置读会带偏；
  行号列由样式收掉（`styles/third-party.css` 的 `.tool-diff`），库那套行号留给 git 面板。
- patch 超过 1000 行不再交给库渲染，退回纯文本 patch（库不做虚拟滚动，而工具入参里的改动没有上界，
  git 面板那边由服务端的行数上限兜住）；这种整篇重写也没得切换统一 / 双栏，展示控件一并收起。
- 展示方式（统一 / 双栏、自动换行）在卡片头部靠右就地切换，与 git 面板共用一份偏好（`hooks/use-diff-prefs`，
  默认双栏、不换行）：同屏多张卡片同一切换，改完不必再跑一趟 git 面板。控件默认不出面——
  悬停卡片、展开卡片或键盘 Tab 进来才现（触屏常驻，用 `HOVER_ACTION_CLASS`）；
  出现与否都占着同一块位置（`opacity` 而不是 `display`），不挤动左边那截路径。
- 工具行与卡片头部的路径留尾部：`shortenPath` 从后往前收整段、前缀收成 `…/`（`utils/path.ts`），
  容器再窄时容器右对齐裁左侧——被裁掉的正是那块没信息量的家目录 / 仓库根前缀。
- 摘要报具体工具名与次数，不用粗分类计数；shell 类调用就叫 `Shell`。
- 失败不在摘要里报数与图标，只在展开后各条自带状态图标；**任何层级都不自动展开**。
- 正在处理的那一组（思考还在流，或组内有工具在跑）行尾要出加载指示。
- 生成中提示行内只报「工作中 + 本轮走了多久」（与落定后页脚里的耗时同源），模型此刻在等什么、卡在哪个
  工具、在等谁，以及本步四段的读数都收进浮层：与总耗时并排摆着，那两个数看着像同一件事，得先分辨才能
  读出意思。阶段起点取服务端的 `step_start`（每次模型往返都下发，本端发送时先乐观起表）；审批 / 提问挂起时
  在浮层单列一行（正等着就报「等待权限审批 / 等待你的回答」）——与服务端状态条的优先序同序
  （`server/src/core/session-status.ts`），免得把等用户看成工具慢。
- 用户参与过的交互（提问及其答复、权限确认）要独立成段，不并进聚合行。
- 「回到底部」与自动跟随由「用户是否贴着底部」决定，且**只在用户主动滚动时改写**。
- 生成中的那一轮不报模型与耗时（判断要在投影层做，不能靠条目的 `live` 标记）。
- 对话区与用量面板里的模型与供应商取模型目录里的显示名（「供应商名 · 模型名」，见 `utils/model.ts`），
  目录里查不到才回落该段原 ID——会话记的模型可能已被改配置换掉、目录也可能还没加载到；
  页脚可见行只留模型名（供应商名在 `title` 里），用量面板则是模型名主文案 + 供应商名副文案。
  设置页的模型编辑面不在此列：那里是 `id` 的地盘（见下文「模型设置」）。
- 嵌套的可点行必须用具名 group（`group/thought` / `group/tool`），否则会被外层聚合行的悬停点亮。
- 一屏内的层级只有两档：正文 `text-sm` > 折叠行与摘要 `text-xs text-foreground-subtle`。
- 反色气泡只给用户消息（同一对 `inverse` token 还给 tooltip 这类小面用）：它是「谁在说话」的分界，与面板底上的 assistant 正文一眼分得开；句子成分（引用 chip、附件 token）自带底色，落到反色面上仍照原取法。
- 目录条只负责「跳到哪一条」，不表达滚动进度：刻度间距与消息数无关（会话再长也不会稀稀拉拉），
  档位与级联规则见上表；正在读的那一条由虚拟列表的视口顶端决定，不是滚动百分比。
- 跳转是平滑滚动（落点由虚拟列表的测量给出，长会话里可能差一两条），目标气泡闪一下做定位提示——
  计时从滚动停下来才开始；同时关掉贴底跟随，不关的话流式追加会把视口拽回底部；滚轮落在刻度上时由目录条转交给消息区（它是滚动容器的兄弟，浏览器不会自己转交）。

## 活动面板

三块「跑着但不在视野里」的状态收在一张只读浮层里：子智能体、目标进度、bash 起的后台服务。
实现落位 `business/chat/activity/session-activity.ts`（视图模型）、`business/chat/activity/session-activity-dock.tsx`（位置与展开）、
`business/chat/activity/session-activity-panel.tsx`（面板）。

| 元素 | 取法 |
| --- | --- |
| 位置 | 对话区右上角（`top-2 right-4`），面板与摘要条都在这一列里、右对齐 |
| 展开策略 | 看内容列（`max-w-4xl`）**两侧的留白**：够放面板（22rem，含边距）时默认展开、整屏落在内容列右侧、不压正文；不够（窄窗口、开着工作台）时默认收成一条摘要条，点开才压在内容列上。用户手动收起 / 展开过就按用户的选择 |
| 摘要条 | `bg-popover` + `ring-1 ring-border-strong` + `rounded-xs`；摘要三段各报一个数（`2 个子智能体 · 1 个服务 · 目标进行中`），`·` 连接；目标那段跟着状态说话——进行中报「目标进行中」，暂停 / 中断报「目标已暂停」（具体原因在面板与目标栏里） |
| 面板 | `w-80` + `rounded-xl` + `bg-popover` + `shadow-dialog` + `ring-1 ring-border-strong`；高度上限按对话区实测高度收口，内部滚动 |
| 三段 | 子智能体（进行中在前）/ 目标（状态 + 目标 + 第 N 轮 + 用量 + 最近一轮结论）/ 后台服务（地址可点复制 + 进程名）；子智能体段标题右侧是 `进行中/总数` |
| 工具行入口 | 子智能体工具行的尾部 chip（`bg-muted` + `rounded-xs`），**默认收起也可见**；点它开面板并高亮定位到那一条 |
| 定位高亮 | `scrollIntoView({ block: "nearest" })` + 1.6s 的 `ring-1 ring-ring/50` |

- 只读：暂停 / 恢复 / 清除 / 预算仍留在目标栏（`GoalBar`，现在是输入卡的上沿条）；决策面板打开时它随输入区一起被底衬盖住，那段时间「目标在跑」只由这段摘要表达。
- 子会话的完整往来交给现成的小窗；面板不内联实时过程，只给「描述 + 最近一步 + 状态」。
- 后台服务只列**当前可连**的：探不到的由服务端移出清单，面板不留「已停止」这类只剩历史意义的行。
- 层级取 `z-10`（低于所有 Portal 弹层），与「回到底部」错开位置（那个底部居中）。
- 没有活动时什么都不渲染（哪怕留白够）——默认展开只在「真有事可看」时成立。
- 用户手动收起 / 展开过就按用户的选择，不再随窗口宽度或活动变化自动翻。
- 空态（还没有消息，`MessageList` 整块不渲染）不出摘要条；子会话里不挂面板。

## 输入区

输入区是「在哪儿干活 + 说什么」两件事：新会话（草稿态）分两层——外层灰底条（项目 / 分支）与内层白卡，
已有会话只剩白卡（「在哪儿干活」不再是待定的事）。

| 元素 | 取法 |
| --- | --- |
| 外层容器 | 草稿态 `rounded-xl bg-muted/50`；两种情况都是粘贴 / 拖拽的落点 |
| 项目 / 分支条 | 只在新会话里渲染：首行 `px-2 py-2`（与列表行同高），项目 chip 可下拉（`rounded-md px-1.5 py-0.5 text-xs` + `hover:bg-state-hover`），分支 chip 只读、只在确实是 git 仓库且取得到分支名时出现 |
| 输入卡 | 内层 `rounded-lg bg-popover` + `ring-1 ring-border-strong`，聚焦只把 ring 换成 `ring-ring`（颜色变、粗细不变）；编辑区 `px-3 py-3`、`min-h-16`、`max-h-55`（消息「编辑重发」复用同一个编辑器） |
| 目标条（卡的上沿） | 已有目标且未完成时它是卡的**第一个子节点**（`Composer` 的 `topBar` 插槽）：`rounded-t-lg bg-muted/50` + 下沿 `border-b border-border`，自身不画外框——宽度、居中与圆角都随卡，内边距 `px-3 py-1.5`（与编辑区左缘对齐，整条 36px）。行内三组：目标文字 > 状态（`size-1.5` 圆点 + 文案，进行中 `bg-primary`）> 元数据（逐轮记录 · 用量）。右侧暂停 / 恢复 / 清除与行内两处入口同为 `ghost` 的 `xs` 档按钮（`h-6`），悬停说明走 Tooltip |
| 目标条降级 | 容器窄于 36rem 时主行只留目标 · 状态 + 暂停 / 恢复，`⋯` 再**往上展开一行**（不是弹层，正上方多一行）放逐轮记录、用量与清除——同一份控件，两处不会同时在屏上；动作文案同时收起只留图标（可访问名走 `aria-label`），阈值与输入区工具栏同一档。不折行：目标 `min-w-0 truncate` 且不撑满行——撑满会把状态推到行尾。次级说明（下一步）缩进 `pl-6`（图标 16 + 间隙 8）与目标文字左缘对齐；逐轮列表跟着它的入口走——宽屏在主行下方（同样 `pl-6`），窄屏铺在 `⋯` 那一行里（容器查询二选一），收起那一行时把列表一并收掉。逐轮行允许折行 |
| 编辑区结构 | 段落、文本、硬换行、有序 / 无序列表（可 `Tab` 缩进嵌套）与三个原子 mention；**列表标记要显式恢复**——Tailwind 预检把 `list-style` 清掉了，编辑区自带一份（与消息区 `.md-content` 同一口径）|
| 编辑区按键 | `Enter` 发送、`Shift+Enter` 换行；**在列表项里 `Enter` 是续行**（空项回车退出列表），此时不发送——列表里按发送键或退出列表后再回车才发出。**触屏一律不发送**：软键盘的换行键报的就是 `Enter` 且没有 Shift，移动端回车只换行，发送走发送键 |
| 工具栏 | 左 `+`（附件 / 技能）· 模式 · 权限；右 模型 · 思考 · 发送 / 停止。均为无边框的 `text-xs` 轻量按钮，图标 `size-icon-sm`（模型 `Cpu` 与思考 `Brain` 相邻，两个入口一起读成「用哪个模型、花多少推理」）。模式是唯一的全局状态，只留文案：不带图标也不带下拉箭头，因此任何宽度下都看得见当前模式；其余四个触发钮也不带箭头，可下拉靠悬停底色与弹层本身表达。模型触发钮显示目录里的显示名（「供应商名 · 模型名」，见 `utils/model.ts`），目录里查不到才回落原 ID |
| 工具栏降级 | 整行不换行、不横向滚动：容器窄于 36rem 时带图标的选择器（权限 / 模型 / 思考）文案整条收起（`hidden @[36rem]:inline`，无障碍名回落到 `title`），只留图标，模型名按剩余宽度截断。阈值用**容器查询**而不是窗口断点——输入卡的宽度由分栏与面板共同决定；`@container` 落在这行工具栏上 |
| 建议行 | 只在空态出现，排在输入卡**下方**（`rounded-xs` + `border` + `text-xs`，带 `size-icon-sm` 图标），点击填入输入框而不是发送 |
| 建议菜单 | `/`（中文输入法下也认 `、`）与 `@` 的候选面板：宽度与左缘跟随输入卡（不再是固定宽度），条目一律单行（名称占剩余宽度、描述各自截断），高度上限 `max-h-64` 内部滚动。方向键在列表内移动高亮并把它滚进视野（到头回绕，第一条往上即最后一条），选中项始终可见。两个触发符都只限文档开头；选中后落进正文的都是 `/name` |
| 空态 | 品牌图 + 按时段问候语，与输入卡同属居中一列 |

- 目标条随输入卡走：卡在哪儿它就在哪儿（hero 态两者同属一列、一起居中），决策面板打开时它跟输入卡一起被底衬盖住。
- 空态与对话态**共用同一个输入卡挂载点**（父节点不变）：hero 只让外层容器 `justify-center` 并把问候渲染在输入卡上方。
- 输入区整列居中：已落会话时与消息列同宽（`max-w-4xl`），草稿态（`sessionId === null`）收窄到 `max-w-2xl`——
  此时输入卡与问候语自成一块，与消息列无关；外层容器自身不铺底色（宿主面板已是 `bg-surface`）。
- 工具栏弹层关掉后的焦点（`usePickerCloseFocus`）：**在弹层里选完 / 按 `Esc` 关掉都把焦点交回输入区**——
  那条路径上 Radix 会把焦点还给触发钮，而工具栏的下一步总是接着打字；交还在 `onCloseAutoFocus` 里做，
  即弹层真正卸载那一刻——早了它自己的 FocusScope 还开着焦点陷阱，聚焦弹层外会被 `focusin` 拉回去。
  点在别处不插手，焦点跟 Radix 默认口径走（模态下拉关闭时会把焦点收给触发钮）。输入区传的就是 `focusEditor`。
- 模式 / 权限 / 思考三个选择器都用菜单的 radio 组（选型见 `components.md`），弹层开在触发钮上方（`side="top"`）；
  带副标题的模式 / 权限固定 `w-72`，只有档位名的思考收到 `w-40`。模型选择器不在这条口径里：它要按 provider 分组，
  用 Popover 列表（`w-80`），只有触发钮与另三个同形（`PICKER_TRIGGER_CLASS`）。
- 选择器的选项行：图标占一列（`items-start`），标题与副标题都从图标之后起排，间距 `gap-1.5` / `gap-1`；
  带副标题的行 `py-2`，只有标题的行 `py-1.5`；选中打勾跟着标题行走（单行 `items-center`、带副标题 `items-start`）。
- 项目弹层取「搜索行 + 单行条目」：面板 `rounded-xl`；搜索行一律用 `base/input` 的 `InputSearch`（`h-11`）；
  条目行 `px-2 py-3` + `gap-2.5`；名称重名的才在名字后补父目录名，全路径落在条目的 `title`。

## Markdown 渲染

正文由 `styles/markdown.css` 的 `.md-content` 一层渲染，解析与流式交给 `streamdown`
（唯一入口 `business/message-response.tsx`，对话正文、md 预览、压缩摘要共用）。

- 字号分两档：正文与表格 `text-sm leading-prose`（表格是读的东西，不降档），代码块 `text-xs`。
- 标题 `mt-5 mb-2`（首个元素不带上边距），字号贴着正文：h2 比正文大 1px（`text-heading-2`）、h1 再比 h2 大 1px
  （`text-heading-1`），h3 及以下与正文同档（`text-sm`）；层次主要靠字重。
- 表格是一张**卡片**：卡片画在 `table` 自身（`rounded-lg border border-border` + `w-max max-w-full overflow-x-auto`），
  三处 `.md-content` 入口（对话正文、md 预览、全屏表格预览）因此长得一样；
  分隔只用横线（表头下一条 `thead tr:last-child th`、行间若干 `tbody tr:not(:last-child) td`），末行不画，交给卡片下边框收尾；
  表头 `bg-muted/50` 淡底色 + 字色弱一档（`text-foreground-subtle`），单元格 `p-3`（与正文同字号）且**默认不换行**
  （列多时靠卡片自己横向滚，不把内容挤成竖条）；宽表仍然只滚表格自身。
  streamdown 默认那层「卡片 + 独立滚动容器」已由 `business/markdown-table.tsx` 整份替换，不要把它加回来。
- 表格操作区：排在卡片**上方**、右对齐的一行（`min-h-7` 常驻占位，悬停或键盘聚焦时才现），
  表格级操作统一加在这里（`business/markdown/table/markdown-table.tsx`，按钮取 `IconButton`，`label` 兼作悬停说明），
  不再盖在表格右上角。
  当前四项：自动换行（开关，`aria-pressed` + 按下态底色，偏好落 localStorage 见 `business/markdown/table-prefs.ts`——
  对话列表是虚拟滚动的，只存在组件里的开关滚出去就没了；这一份偏好**同屏所有表格共用**，
  模块级 store + `useSyncExternalStore`，见 `hooks/use-table-wrap.ts`）、复制为 Markdown、导出 CSV、全屏查看。
  导出与复制都读眼前这张表的 DOM（`business/markdown/table-export.ts`），转义交给 streamdown 的表格工具（与它内建控件同一口径），
  不另存一份 markdown 源。
- 正文图片：本站附件先取字节转 blob 再渲染（`business/attachment-image.tsx`）；外层用 `span`，因为正文里的图片常落在 `<p>` 里。
- 列表标记用 `text-foreground-subtle`；GFM 任务列表去掉圆点。
- 行内 code 与代码块都只换底色（`bg-muted`）不换色相；行内 code 取 `text-xs`，与正文的差距由底色承担。
- 代码块右上角有悬浮复制按钮（`business/code-block.tsx`），悬停或键盘聚焦时出现；复制的是源码原文，
  成功图标换成对勾并保持 1.5s（`business/copy-action.tsx`，消息页脚的复制共用）。
- Mermaid 图块（`.md-mermaid` + `.md-mermaid-viewport`）：底色用卡片色、`p-3`、圆角描边同代码块；
  高度上限 `max-h-105`，宽图在块内自己横向滚（`svg` 保持 `max-w-none`）。图源不完整或语法不支持时回落成代码块，不弹错误面板。
- 全屏查看（`business/fullscreen-dialog.tsx`，走 `openDialog`）：窄屏铺满、桌面 `90vw × 86vh`；
  图表与图片共用可缩放视口（`business/zoomable-preview.tsx` + `hooks/use-zoom-viewport.ts`）：
  视口内拖拽平移、滚轮平移、`Ctrl` 加滚轮与加减号键缩放，比例下拉给 50% / 100% / 200% 与「适配窗口」「重置缩放」。

**子智能体 / 技能 / 命令**：三页同构，都是「两段列表 + 声明式编辑弹窗」。第一段「本机与项目」放可编辑条目
（名称 + 来源徽标 + 说明 + 文件路径，右侧编辑 / 删除图标按钮），第二段「插件与内置」只读；被同名来源压住的条目
在行内写明「被同名项覆盖：<路径>」，解析失败的文件收在页底错误区（红框逐条列出路径与原因）。空态给出「新建」出口。

- 弹窗按类别换字段组：角色多出类别（分段控件）、可用工具、模型、思考档位与两个开关；技能只有说明与正文；
  命令有说明、参数提示与正文。新建时可选全局 / 当前项目，没有工作目录时只留全局并注明原因。
- 命名规则（小写、连字符）在弹窗里先挡一道，服务端再按同一口径校验。
- 新建与删除即时落盘（同 MCP、插件）；页头的保存区提交的是**配置草稿**，与资产改动无关。改动对**新会话**生效。

- 保存语义：打开设置即拉草稿，改动只落在草稿里；「保存并生效」提交后关闭面板，「取消」丢弃草稿回工作区。
- 外观分区例外：它读写的是设备本地偏好（`localStorage`），改动即时生效并落本地，不进草稿。
- 外观分区的控件选型：配色主题与深浅模式、界面密度、语言用分段控件；界面字号用滑块（14–22px，右侧显示当前值）；
  界面字体用下拉（等宽固定为系统栈，不给设置项）。
