# 变更日志归档（2026）

`CHANGELOG.md` 只留「未发布」与最近几个已发布版本的摘要，各版明细按发布年份归档到这里（同年合并、版本倒序）。

## [0.6.1] - 2026-11-06

### 修复

- `ucode start` / `restart` 不再把 `service.json` 里的监听地址重置成环境文件里的默认值
  （设置页开启的「局域网访问」重启后仍然生效）。

## [0.6.0] - 2026-11-06

### 新增

- `ucode` 补齐标准命令：`help`（含子命令说明）、`-v` / `version`、`logs`（`-f` 跟随、跟得上轮转）、`open`、
  `doctor`（安装与环境自检）、`password`、`update`（查 npm 最新版，不自动安装）、`completion`（bash / zsh / fish）；
  `start | stop | restart | status` 可省去 `service` 前缀（`service …` 仍可用），`status` / `doctor` / `update`
  支持 `--json`。

## [0.5.0] - 2026-11-06

### 新增

- **可以装成全局命令**：`npm install -g @easyx/ucode` 后拿到 `ucode` 命令（服务、Web UI 与随包技能
  整个装好），不需要再 clone 仓库。
- **`ucode service start | restart | stop | status`**：后台启动并脱离终端，日志追加到
  `$APP_HOME/app/service.log`（超过 5 MB 时下次启动轮转成 `service.log.1`，只留最近两份）；
  `start` 首次回显登录密码、已在运行时不重复起，`restart` 用来换版本后接着跑，`status` 以退出码区分是否在运行。
- **旧的 `--status` / `--restart` 参数移除**：改由 `ucode service status | restart` 承担，仓库里的快捷写法是
  `pnpm status` / `pnpm restart`（`pnpm start` 仍是前台启动）。
- **工作台的改动列表覆盖 submodule**：子模块内的改动按「子模块路径/文件」与主仓库的文件同列，指针变更仍单独一条；
  文件 diff 与「全部改动」都在子模块仓库里对比（展开未变更区域也能取到原文）。
- **工作台终端与内置浏览器面板可经中继使用**：隧道协议升到 v2（`request.upgrade` 把一条流转成 WebSocket，
  新增 `close` 帧回传关闭码，数据帧区分文本与二进制——终端的上行约定是文本帧）。只在按路径访问
  （`/d/<设备 id>/`）时可用，子域寻址仍不支持。v1 客户端会被握手拒绝，需与服务同批升级。
- **中继里点设备直接打开它的 UCode**：中继前台的「我的设备」多一个「打开」入口，经隧道直接进入该设备的界面；
  单域名部署下地址是 `/d/<设备 id>/`（不用配泛域名，与中继同源、不再单独登录），设备离线时不给入口。
  被打开的设备必须是含该改动的版本（页面靠服务端按 `x-hub-base-path` 改写 `<base href>`）。
- **一键把中继的模型端点加成本机的供应商**：设置 → 服务 → 中继里点「添加为中继供应商」，服务现拉中继的
  `/v1/models` 并写入一条普通 provider（固定 id `relay`、名称「中继」、`baseUrl` 为 `<中继地址>/v1`、
  apiKey 用设备令牌），随后可在模型设置里选它的模型；对话由中继用运营方配好的厂商转发，用量与计费记在中继侧。
  重复点只刷新模型清单；清单拿不到（中继不可达 / 设备令牌失效 / 中继后台没配厂商）就报错而不写占位模型。
  接口 `POST /api/v1/hub/provider` 与手工配置方式见 `docs/hub.md`。
- **内置资产可从中继下发更新**：随包的内置技能与提示词命令不再只能等产品发版——服务启动时（以及登录中继后）
  主动向中继拉清单，按 `id` + 版本只下载缺失或版本不同的，逐文件 sha256 校验后物化到 `$APP_HOME/app/builtin/`，
  对新会话生效；中继不可达只是「拿不到更新」，不影响启动。含可执行内容（hooks / bin / MCP / TS 扩展）的资产
  **只落盘不生效**（`app/builtin/quarantine/`），等签名与显式信任。接口与发布方式见 `hub/docs/builtin-assets.md`。
- **设置里新增「中继」一节**：填中继地址与账号密码即可接入——一次登录同时换到中继令牌、把本机登记为设备并建立隧道；
  页面显示登录账号、设备标识与隧道状态（连没连上、上次为什么失败、重连了几次），可随时退出登录
  （清设备绑定与登录凭证、尽力吊销中继侧那台设备、保留地址这一部署项）。断线按指数退避自动重连，服务重启后按已存配置自动接回。
- **UCode 服务内置中继（hub）客户端**：新增 `/api/v1/hub/status|login|logout` 三个接口；`service.json` 的 `relay`
  多了 `token` / `username` 两个字段（旧文件不影响：缺了按未登录处理），配置齐备时服务自动向中继建立出站隧道，
  公网请求经中继回灌到本机的同一套 `/api/v1`。
  接入步骤与连接行为见 `docs/hub.md`。
- **B 端交付可预置中继地址**：`@ucode/brand` 扩为「品牌 + 部署」，新增 `deployment.hubUrl`（默认 `null`
  表示未接入），B 端交付改这一处就能预置中继服务地址；本机设置页后续可覆盖。
- **输入框支持方言容器**：行首打 `:::` 就能挑一条命令或技能，插入 `:::command[名字]` / `:::skill[名字]`
  容器（内容就是参数）；围栏在输入框里显示成芯片，写错（名字不存在、没有收尾 `:::`、容器里套容器）
  就地标红并给出原因，发送前也会拦住。粘进来的文本若含会生效的容器围栏、`@` 引用或 `attachment:` 附件
  一律按字面处理（转义符淡显），来路不明的文字不会替你把文件读进上下文。
- **工作台终端**：编辑器区以标签打开本机 PTY，按工作目录归口；关标签即结束进程，切会话不结束。
- **窗口标题反映待处理状态**：有会话在等你（审批 / 问答 / 计划）时写成「待审批 · UCode · AI 对话」，
  否则有未读时写成 `(2) UCode · AI 对话`；切到别的标签页也能看出有人在等。
- **对话里能直接看工具产出的图片**：截图与 `read` 到的图片在工具卡展开后直接铺出来（点开放大到全屏），
  刷新与重开应用后仍在；旧工具输出的正文被清理后图片也保留，并标明「已从模型上下文清理」。
- **生成中再发消息改成排队**：对话跑着的时候照样能发——输入进队列，本轮（含工具调用）结束后依次送出；
  输入卡上沿多一条「排队中」，列出自己发出去的那几条，可整条撤回并回填输入区（`messages/prompt` 的回执多一个
  `queued`，新增 `messages/dequeue`）。此前生成中按发送没有任何反应，草稿留在输入框里，看起来像发送失败；
  发送恰好落在本轮收尾的那一小段也不再报「会话正在生成」，同样排队。生成中同时也能执行 `/new`、`/models`
  这类内置命令了（原先一律被挡住）。生成中的发送区只留一个键位：PC 上是「停止」（要排队直接回车），
  触屏改成一个上拉菜单，里面是「停止生成」与「发送（本轮结束后送出）」。
- **设置里能查看与维护项目级记忆**：设置 → 记忆按项目列出已保存的记忆（标题 + 描述，展开读正文），
  悬停可改标题与正文、可删除（带确认）；项目名取侧栏改过的名字并标出该项目的记忆开关是否生效，
  读不到对应项目的目录也照列。新增记忆仍走模型侧的「记住」与每轮结束后的自动回顾；
  改动会让已装配的会话按新记忆重装（新增 `memory/list|read|update|delete`）。

### 变更

- **环境文件的优先级多了一档**：显式环境变量 > 从 cwd 向上找到的 `.env(.prod)` > 随包的
  `defaults/default.conf`；最后一档只在 npm 安装形态下生效（源码树里漏写环境文件仍然直接报错），
  于是装完就能跑，不用自己写配置。
- **中继（hub）改用 SQLite**：不再需要数据库容器，数据落在中继的应用数据卷里（`volumes/app/data.db`），
  备份与恢复按整文件处理；根侧的 `pnpm db:hub:up` / `pnpm db:hub:down` 随之移除，`pnpm dev:hub`
  首次启动自动建库文件。中继侧的其余行为变化（会话有效期 24 小时、登出即作废该账号其它会话、
  自助注册默认关闭等）记在 `hub/CHANGELOG.md`。
- **中继（hub）改为独立仓库**：`hub/` 从本仓的子目录变成 git submodule（仓库 `lvyueyang/ucode-hub`），
  自带 workspace、锁文件与工具链——本仓的 `pnpm install` 不再装那棵前端依赖树，`pnpm check` 也不再跑它的
  typecheck 与测试（要改 hub 就进 `hub/` 安装与检查）。隧道协议两边各留一份副本（本仓 `packages/hub-protocol`），
  一致性由 `pnpm verify` 逐文件比对，改协议要同时改两处。子模块未初始化时先 `git submodule update --init`。
- **侧栏项目行把操作收进「更多操作」菜单**：项目名拿到整行剩下的宽度，重命名与记忆开关收进菜单（原先四个
  图标按钮并排占着右侧，名字长一点就被挤掉）；开着记忆的项目，名称前的文件夹图标染成信息色，悬停整行说明
  「此项目已开启记忆」并带上目录。
- **移动端工作台换成顶部视图条**：竖排的活动栏只在桌面端出现，窄屏下换成一行的视图切换压在列表页顶部，
  切视图不再占掉 40px 宽度；看文档时标签条最右补一个「收起面板」，满屏抽屉有了自己的退出口
  （此前只能点对话区那颗被抽屉盖住的开关）。
- **窄屏下 diff 的行号收成一列**：350px 的内容区里原先旧 / 新两颗行号要吃掉近 100px（还带 100px 下限），
  代码得横向滚才能读；现在收成一列（有新号显新号、删除行显旧号），展示方式与换行仍按自己的偏好。
- **窄屏下 diff 的工具条只留图标**：「统一 / 双栏」两项的文案与「全部改动」里的「N 个文件」在工具条容器
  窄于 30rem 时收起，省下的宽度让给文件名（图标按钮本就没有文字，不受影响）。
- **对话里命令与技能的显示与输入框同形**：技能 / 命令芯片改排在气泡正文开头（技能按注入顺序、命令最后，
  各跟一个空格再接参数），不再在气泡上方单开一行；与输入框、编辑重发看到的是同一套顺序。
- **对话里的进行中提示报出时间花在哪一段**：行内报当前在等什么与等了多久，悬停展开本步明细——本次请求的
  等待模型响应 / 等待首帧 / 生成 / 执行工具四段加「其中等用户」的时长，再带本轮总耗时；上游排队占掉一轮
  大半时间时，原先只看到「工作中」看不出卡在哪。状态起点由服务端在每次模型往返开始时下发，所以批准计划、
  目标续跑这类不经过输入框的轮次也有读数；审批与提问挂起时改报「等待权限审批 / 等待你的回答」，不把
  等用户看成工具慢。
- **记忆开关支持按项目单独设置**：全局那个开关改为「默认值」，侧栏的项目行上可以单独开 / 关（入口在项目行的
  「更多操作」菜单里），项目显式设过就用它、没设过跟随全局；改完立刻生效（已装配的会话按新值重装）。
- **对话里的编辑 / 写入独立成卡片**：不再折进「使用了 2 个 编辑」的聚合行，每次写盘自己占一张可折叠卡片，
  header 是「编辑 / 写入 + 路径」，展开看行级 diff。
- **终端输出流改用 WebSocket**（原 SSE + POST）：结束与拒绝由关闭码表达，不再走 SSE 事件。

### 修复

- **只发一条命令开的新会话不再被起成「空会话」这类标题**：`/review` 这种无参数、无正文的调用原先拿一份空料
  去问标题模型，模型回的「空会话 / 无内容」被当成合法标题写死；现在取料回落到调用名（`/review`），
  真的没料就不问，交给本轮结束后的补试用完整交流命名。
- **会话标题生成失败会自动重试**：投递首轮时那次没产出（模型给多行、带「标题：」前缀、把回答当标题，
  或调用超时 / 限流）就在轮末用完整交流再问，最多 3 次（含首次），重试时把格式要求再说一遍；
  此前只在首个轮末补一次，而并行调用比首轮慢时那次触发会被跳过，会话于是长期没有标题。
- **未命名的会话一律显示「新会话」**：不再拿首条用户消息当名字（它仍留在会话摘要里供命令面板搜索），
  重命名弹层也不再预填那句话。子会话详情小窗是例外：那里回落委派任务的首句（子会话不会被自动命名，
  全部叫「子会话」等于没标题）。
- **终端不再继承宿主环境**：原先整份 `process.env` 透传，宿主带进来的 `NODE_ENV` 会污染终端里的构建。
- **触屏上回车只换行，不再把消息发出去**：软键盘的换行键报的就是 `Enter` 且没有 Shift，原先的
  「没有 Shift 的回车即发送」在移动端等于每次换行都发一条；计划决策表单的意见框同理。
- **对话区的工具块显示工具名与调用形态**：原先一律「工具」+ 参数 JSON，现在内置工具给中文标题、
  未登记的（MCP 工具等）直接显示工具名，浏览器工具另给出 `click @e1a2` 这类调用形态。
- **已批准的越界目录规则在 Windows 上不再失效**：规则串是 posix 口径而匹配对象是平台原生路径，
  于是「D:/app/** 本会话内不再询问」在子路径上从不命中、每次都重新弹审批；现在两侧都归一分隔符。
  顺带修掉盘符根文件（`D:/x.txt`）的授权范围会写成 `D:/**`（整盘放行）。
- **目标卡片的「工具调用 N 次」不再恒为 0**：原先取「最后一条 assistant 消息」的工具调用数，而那一轮
  既然已落定，那条消息在结构上就没有待执行工具；改取本轮区间内的步级记录之和（同一处的「连续无进展」
  判定一并修好，它原先也把每轮都当成没调用过工具）。
- **移动端工作台的背景不再半透明**：窄屏下它是铺满屏幕的主面板，原先却用了外壳 / 侧栏的玻璃底
  （84% + 模糊），后面遮着的对话会透出来。
- **`/` 与 `@` 候选菜单的方向键跟随滚动**：高亮原先只改类名、从不把选中项滚进视野，且每次重建
  整张列表会把滚动位置归零——候选一多，高亮走出可视区就像方向键「到头了」（按 Enter 却会选中那条
  看不见的项）。现在方向键只切换高亮并把它滚进视野，头尾回绕。

### 移除

- **浏览器画面帧流**：删掉 `GET /api/v1/browser/stream`、`POST /api/v1/browser/ticket` 与 SDK 的 `createBrowserSocket`。

## [0.4.0] - 2026-11-06

### 新增

- **工作台终端**：编辑器区以标签打开本机 PTY，按**工作目录**归口（同目录的会话共用同一批终端）——关标签即
  结束进程，切会话不结束。终端不落库、不进会话记录，也不套 agent 的命令拦截。输出流走 WebSocket
  （原 SSE + POST），依赖新增 `node-pty` 与 `@xterm/xterm` / `addon-fit` / `addon-attach` / `addon-unicode11`。
- **外观新增「终端字体」**（设置 → 外观）：默认与代码字体同源，也可换成 Nerd Font 家族——提示符里的图标
  字形（私有区码位）只有这些字体才有，缺字形会画成方框；没装的人与默认档完全一致。
- 新增 `pnpm check:fast`（中途收窄：跳过测试，只查改动文件的 biome + 全仓 typecheck + 约定校验）与
  `pnpm verify -- --only <项名>`（只跑指定校验项）。
- **浏览器工具支持表达式求值**：`browser_act` 多一个 `eval` 动作，在页面里求值一段表达式并回传结果
  （字符串原样、其余紧凑 JSON，上限 4000 字符）——用来读 `getComputedStyle` 这类快照看不见的计算值，
  UI 走查因此不再依赖外部的 `agent-browser` CLI。
- **对话里的图表可下载为图片、可看原代码**：图右上角与表格同一套操作——下载存成 SVG（矢图、文字可选，
  文件名带导出时刻）、查看原代码（弹层里是高亮好的 mermaid 源，可复制）。

### 变更

- **工作台的改动统计挪到分组标题上**：代码管理视图里，全量增删数原先占着「改动 / 历史」右侧的位置、
  与实际看的分组脱节；现在跟到「已暂存」/「未暂存」标题后面（与该组文件数同行），原位置改显当前分支名
  （分离头指针时写明）——一眼知道在哪个分支上改。
- **对话里的改动卡片换成工作台同一套 diff**：展开后是带语法高亮的 diff（`@git-diff-view/react`，
  与 git 面板同一渲染件、同一份展示偏好），统一 / 双栏与自动换行就在卡片头部靠右切换（默认双栏、不换行），
  悬停卡片或展开时才现；未变更区域可逐段展开，整块高度仍收在 `max-h-96` 内滚动。卡片里不报行号——
  patch 由改动片段拼成，行号从 1 起、不是文件里的位置；上千行的整篇重写退回纯文本 patch。
- **工具行里的长路径改为留尾部**：原先从尾部截断，改一个深目录里的文件时光看得到无关的前缀、看不见文件名；
  现在从后往前收整段、前缀收成 `…/`（如 `…/chat/tool/working-indicator.tsx`），空间不够时裁掉的是左侧前缀。
- **对话里的进行中提示报出时间花在哪一段**：行内只报「工作中」与本轮已走的时间，悬停展开本步明细——本次请求的
  等待模型响应 / 等待首帧 / 生成 / 执行哪个工具四段加等用户那一行；上游排队占掉一轮大半时间时，原先
  只看到「工作中」看不出卡在哪。阶段起点由服务端在每次模型往返开始时下发，所以批准计划、目标续跑这类
  不经过输入框的轮次也有读数；审批与提问挂起时浮层里改报「等待权限审批 / 等待你的回答」，不把等用户
  看成工具慢。
- **命令菜单的触发符除 `/` 外也认 `、`**：中文输入法下常常打不出半角斜杠，顿号是同一个键位的顺手选择；
  两个触发符都只限文档开头，选中后落进正文的仍然是标准的 `/name`。
- **`/` 与 `@` 的候选菜单宽度跟随输入卡**：原先固定 320px、与输入框对不齐；条目名称与描述改为单行
  截断（描述不再整段换行把面板撑高）。
- **触屏上消息操作常驻显示**：复制 / 分叉 / 编辑、代码块与表格的悬浮按钮在触屏（`pointer: coarse`）下
  不再依赖悬停——原先移动端要么看不到入口，要么是一枚看不见却点得到的盲区。
- **一条消息可以带多条技能**：`messages/prompt` / `messages/edit` 的载荷改成 `command`（最多一条）
  + `skills`（可多条，各自带参数），服务端按顺序逐个注入技能正文；正文里不再带命令名，手打的
  `/name 参数` 与从 `/` 菜单选的命令走同一条客户端定形（见 [`docs/api.md`](../api.md)「输入载荷」）。
  名字对不上清单（模板被删、技能文件读不出来）时返回 400，不再静默当普通消息投递。
- **技能块的参数进属性**（`<skill name="…" location="…" args="…">`）：原先接在块之后，一条消息带多条
  技能时块外的文本分不清属于哪个技能。历史会话不受影响（读侧两种形状都认）。
- **只读模式（plan / ask）不再一刀切断掉 `bash`**：`ls` / `cat` / `rg` / `find` / `git log` / `git diff` 这类
  只读命令可以直接跑，写盘、构建、测试与装依赖仍然阻断；浏览器工具改成「观察面放行、页面操作看实例」
  （判据见 [`docs/modes-and-permissions.md`](../modes-and-permissions.md)）。
- **目标栏改挂到输入卡的上沿**：原先它是面板底部的通栏带，现在做输入卡的第一个子节点，宽度、居中与圆角
  都随卡走（`Composer` 因此多一个 `topBar` 插槽）；窄容器（36rem 以下）里主行只留目标与暂停 / 恢复。
- **去掉 `browser_open` 的按站点审批**：它曾是同类里唯一的审批面，而 `bash` / `webfetch` / `websearch` 都
  默认放行、外联面还更宽；自测与走查每次开页面都要确认不划算。站点级把关改由权限档位与只读模式对
  `browser_act` 的阻断承担。

### 修复

- **同一条消息不再出现两条**：消息流与快照走的是不同连接，晚到的那个事件原先会把快照里已有的一条再追加
  一次（新建会话发出首条消息时最容易撞上）；现在快照覆盖过的事件一律按序号丢掉，同一条消息重复到达
  也只保留一条。
- **命令消息的参数不再被当成纯文本**：气泡与编辑态现在按同一遍标记扫描还原参数里的 `@引用`、图片与
  附件，位置就是用户当初放的位置（此前只当字面文字，图片还会在附件行里重复出现一次）。
- **`browser_act` 不再把 SPA 路由当成导航**：原先用 URL 变化判断，`pushState` 那种路由会被误报成
  「页面已跳转、编号已失效」——在 UCode 自己这类 SPA 里走查，几乎每次开面板都要白跑一次快照。
  现在按文档身份（`performance.timeOrigin`）判定，地址变了而文档没换时编号仍然有效。
- **终端不再继承宿主的运行环境**：原先整份 `{...process.env}` 透传，宿主带进来的 `NODE_ENV` 会让终端里的
  `vite dev` 误判为生产模式，报出 `opentype.parse is not a function` 这类只在终端里出现的怪错。现在按前缀
  剔除 `npm_*` / `pnpm_config_*` / `APP_*` 与 `NODE_ENV` / `NODE_OPTIONS` / `TERM` 等宿主标记，用户级配置保留。
- **终端失联不再无声卡死**：输出流被判终态（`exit` / `gone` / `unauthorized`）时界面给出说明与「重新连接」
  入口，不再冻在最后一帧。
- **安装期补 `node-pty` 的 `spawn-helper` 执行位**（根 `postinstall`）：npm 包里的预编译 helper 是 `644`，
  缺执行位起 PTY 会 `posix_spawnp failed`。

### 移除

- **hub 删掉基座自带的示例业务**：`news`（表 / 服务 / 前台页 / 管理页 / 权限码 / 菜单与文案）与 `/admin/demo` 示例页（含 AI 富文本演示）一并删除，管理端菜单随之少掉「业务示例」「测试页」两组；`news` 表由迁移 `20261020054448_swift_skin` 删除。

### 修复

- **`pnpm start -- --restart` 这类参数透传一直不工作**：pnpm 会把 `--` 一并传给 node，CLI 遂报「未知参数」
  （与 `shellEmulator` 无关，关掉也一样）。现在 CLI 丢弃裸 `--`。

- **技能命令的边界可被正文伪造**：`/skill:name` 展开的 `<skill …>` 块原先是手工拼字符串，没走
  `wrapUntrusted`，技能正文里写一行 `</skill>` 就能提前闭合边界——既能把后续文字伪装成对话本身，
  也会让客户端的 chip 解析（按首个闭合标签切块）把剩余正文当成用户原话。改为一律走边界包裹；
  同时补全边界标签名单（原缺 `skill`），并把名单上提到 `packages/contracts`，
  服务端的包裹 / 中和与客户端的解析共用一份（原先两边各写一遍字面量）。

- **桌面端通知的免打扰口径**：原先用页面可见性判定「人在不在」，而 Electron 的可见性只跟踪隐藏 / 最小化
  （仅 macOS 额外跟踪被完全遮挡），所以「切到别的应用、窗口还露着」时恒为可见——桌面端在这种形态下一条
  通知都不发。现在桌面端按窗口焦点判定（web 端仍按页面可见性），判定收进 `lib/notice` 的 `isUserPresent`。
- **桌面端系统通知的投递结果不再假报成功**：主进程原先无论系统是否真的收下都回 `true`，而 macOS 未签名、
  Windows 缺 AppUserModelID 时系统是**静默丢弃**的（`failed` 事件无人监听），界面于是永远显示「已授权」。
  现在监听 `show` / `failed` 如实回报（事件不可观测的平台按提交处理，另有超时兜底），设置页在送不出去时
  提示「系统没有让通知通过」；同一会话的通知改用同一个 `id`，等待 → 完成 → 出错不再堆成一串；
  补 `silent`（提示音由应用自己播，否则双响）；点击回传前先判窗口存活；Windows 补 `app.setAppUserModelId`。
- **改配置不再打回挂起中的会话**：`recycleForConfigChange` 原先只保护「正在生成 / 压缩」的会话，
  等审批 / 等回答 / 待确认计划的会话会被立即丢弃（用户正看着的审批与计划跟着消失）。现在与插件登记表
  变更用同一套保护（`core/pool.ts` 的 `isProtected`），标脏后等它落定再回收。
- **`scripts/verify` 的 layers 校验补上插件宿主的接缝约束**：`harness/pi` / `harness/features` / `platform`
  不得依赖 `harness/plugins`，`core` 取它只许 `import type`；装配期（`harness/setup`）按值构造插件
  hooks 扩展与内置命令是记录在案的例外（原先 `AGENTS.md` 承诺的「`harness/setup` 只许类型依赖」
  与代码不符，已按代码改文档）。

- **流式代码块在高亮与纯文本之间反复抖**：代码块接上 shiki 后没看「这一块还在不在流式」，每来一个 chunk
  都重算一次并先把结果清空，模型边写边闪。现在流式期间只铺纯文本，写完再上色。
- **全屏查看会吞掉 `Cmd` / `Ctrl` + `-`**：图表预览把裸键与修饰键一起拦了，页面缩放因此失效；现在只接管裸键。
- **目标起轮失败时会把目标换回上一个**：`goals/set` / `goals/resume` 的失败分支拿的是请求开头那份会话快照
  （`goalState` 还是写入前的值），而 `GoalService.pause` 只看传入状态是否 `active`：旧目标是 `active` 时
  （如刚重启过服务、目标还没在跑）它会把旧 `objective` / 旧 `id` 写回去——刚设的新目标被静默覆盖，
  界面上只看到一句「生成出错已暂停」；旧目标不是 `active` 时则什么都不写，注释里「别让目标停在 active」
  的意图落空。改为暂停前重读一行。

- **重复的 `ucode.mode` 设置点**：去重此前只看内存里那份上次值（实例创建时为空、重装后重置），
  于是新会话首轮必定写两条相同记录，服务重启 / 换模型 / 换权限档位导致实例重装后也会再写一条，
  消息区里于是每轮都冒出一行「本轮参数」。改为对着会话文件里最后一条设置点去重。

- **每步耗时记录的首 token / 解码两段永远是空值**：`harness/features/telemetry` 等的 `message_update` +
  `assistantMessageEvent.type === "start"` 永远不会出现——pi 的 `start` 帧走的是 `message_start` 事件，
  `message_update` 只承载内容帧。锤点改为 `message_start`（响应头到达）与首个 `message_update`
  （首个内容帧），`ucode.step` 因此新增 `firstEventAt` / `firstEventMs` / `toolNames` / `hasText` /
  `thinkingLevel` 五个字段，登记表同步。
- **刚发出去的消息编辑 / 分叉必然失败**：`message_end` 的实时帧里 pi 还没把消息落盘（事件先于 `appendMessage`），
  服务端只能给一个临时 id，而界面拿这个 id 去调 `messages/edit` 与 `sessions/fork`，于是「发完立刻改」一律
  400（不在活动分支），刷新页面（走快照）后才正常。现在事件总线把这一帧推迟一个微任务，按消息对象身份在
  分支里查回真实条目 id 再下发；查不到（落盘失败）时仍退回临时 id，不丢帧。
  同时修掉编辑态新加的 `@` 引用回放不出 chip：编辑重发漏了「引用标记换算成工作目录相对写法」这一步，
  正文里留下绝对路径，与展开块上的相对 `path` 对不上，现在与首次发送同一条口径。
- 回到前台后界面仍停在上一轮的「工作中」（刷新才收敛）：既有的空闲看门狗靠定时器，而定时器在后台标签页
  会被节流、窗口被冻住时根本不跑，后台期间错过的收尾帧也无人补——现在离开超过 30 秒再回前台、
  且客户端仍认为有会话在生成时，以及**网络恢复时**，都重开一次事件流（新增 `EventStream.restart`），
  按既有的重连路径把会话列表与已打开会话的消息快照一并补齐，并丢掉积压的过期增量。
- 子智能体嵌套进度断流后会卡在「执行中」：`messages/list` 快照新增 `subagents`（服务端在跑的委派清单），
  客户端以快照为准重建嵌套卡片、把快照里已不存在的收敛为已结束——嵌套进度不落盘，只靠
  `subagent_start` / `subagent_end` 增量维护，断流期间错过结束帧就会永久停住。
- 请求与连接都加了超时：SDK 传输层给每个请求挂超时（缺省 30s；拉模型目录 60s、附件上传 120s），
  超时映射为新错误码 `request_timeout`；事件流加空闲看门狗（服务端每 15s 一次心跳，45s 没收到任何字节
  即主动断开重连）——半死连接此前既不会 reject 也不会触发 `onDisconnected`，界面就一直停在生成中或加载骨架。
- 会话正在生成时点 `/compact` 不再显示红色错误横幅，改为一条轻提示（等这一轮结束再压即可）。
- `interactions/respond` 返回 `resolved: false`（kind 不一致 / 请求已失效）时重新取一次待答列表：
  此前本地已乐观移除，对话框会凭空消失而请求仍挂着。
- 服务端发起的动作在客户端缺收尾信号（同类型一起排查并修掉）：
  - 手动压缩与自动压缩的结果都补上了明确出口——`compaction_end` 现在带上规模变化、正常拒绝原因或
    自动压缩失败原因，客户端据此收尾并在需要时弹一条轻提示（以前自动压缩失败是静默的，用户只能等下一轮
    超窗报错）。
  - 实例离池（空闲回收 / 配置变更 / 子会话结束）后补一帧摘要：侧栏的「本轮出错」「等待计划确认」只在池内
    内存里，不发帧会一直挂着；归档路径先发 `session_updated` 再发 `session_archived`，顺序无碍。
  - 重连补齐目标与用量：`sessions/info` 里的目标状态与上下文占用此前只在切换会话时取一次，断流期间错过的
    `goal_update` / `session_updated` 不会回放，现在与其它 store 一致在重连时重取已加载过的会话。
  - 错误帧一并清「压缩中」；会话索引写库失败不再打断收尾（以前会跳过占位释放与摘要补发，会话就停在运行态）。
- `/compact` 在「没什么可压」时不再报错：pi 的 `Nothing to compact (session too small)` 与 `Already compacted`
  属于**正常拒绝**（没做任何事、也不改变会话状态），服务端识别后改走 `compaction_end.skipped`
  （`too_small` / `already_compacted`），界面只弹一条轻提示，不再显示红色错误横幅、也不再把会话标成「本轮出错」；
  真失败（模型不可用、总结被中断）仍按 `compaction_failed` 回传。客户端在 `compaction_end`（`reason: "manual"`）
  就地结束「生成中」——手动压缩不会再有 `agent_settled` 收尾，否则界面会一直停在「工作中」。
- 压缩后界面没有任何痕迹、生成态还会挂住：压缩会重写可见历史（早期条目被摘要替代），而服务端此前不发
  `transcript_reset`，客户端只认消息流事件，于是「实时视图」与刷新后的快照不一致；而手动压缩不会再发
  `agent_settled`，尾部「工作中」也一直转下去。现在手动压缩在 `endRun`（占位释放）之后、自动压缩在
  `compaction_end` 时就地下发 `transcript_reset`，客户端重取快照即得到「摘要 + 保留区间」并把 `running` 校正为假；
  压缩摘要改为「会话已压缩」分隔行（可展开回看全文），压缩进行中的尾部提示改报「正在压缩上下文」且不报耗时。
- 自定义命令在编辑器里显示成 `//review`：命令 mention 不再按 Tiptap 默认实现补一次触发符
  （label 本身已带 `/`），命令提示项、序列化与刷新后的回放都保持单斜杠。
- 侧栏会话的 loading 有时不消失（刷新页面才恢复）：一轮的收尾顺序固定为「先写索引 → 再释放占位 →
  最后补发一帧权威摘要」——此前摘要在占位释放前发出，最后一帧带着 `running: true` 落地，
  客户端只能等重连或手动刷新才把生成态收掉。
- 发送后不再自动触底、「回到底部」随手一亮：贴底跟随与按钮改由一个「只在用户滚动时改写」的状态驱动，
  自己发起的贴底滚动只豁免它引发的那一个 scroll 事件；并在行数或总高度变化时重新落到最新一行。
- 生成中的消息行会闪一下：行 key 改取新增的 `ChatItem.uid`（跨「乐观条目 → 权威条目」不变），
  `message_end` 沿用被替掉条目的 `uid`，快照刷新只对**乐观条目**按位置沿用（服务端条目一律用自己的条目 id）。
  此前 key 取 `id`，而 `message_end` 会把 `live-assistant-N` 换成服务端 id，于是每次落定都卸载重建整行；
  快照刷新时若按位置一律沿用，插入一条记录就会把后面的 uid 整体错位、插入点还会与插入项撞成同一个 uid。

- 设置里的「局域网访问」开关重启后不再生效：`APP_HOST` 此前被当作强制覆盖值，改用「默认值」语义——
  取值顺序 显式（`--host` 或启动前已有的环境变量）> `service.json`（设置里改过的值）> `.env(.prod)`；
  `APP_PORT` 无设置入口，取值 显式（`--port`）> `.env(.prod)`（`service.json` 仅兜底），改端口只需改 env。
- 启动失败（如端口被占用）会污染注册文件的 `pid`：`pid` 改为 listen 成功后再落盘，不再把正在运行实例的
  pid 覆盖成即将退出的本进程，避免 `--status` 误报「未运行」、`--restart` 无法停旧。
- `--restart` 结束旧实例前校验 pid 是否监听在注册端口，避免崩溃遗留的陈旧 pid 被系统复用后误杀无关进程。
- 聊天区的模型选择器只列已接入的供应商：目录里还有 32 个未配凭证的内置供应商，
  选了必然报 `Provider is not configured`。
- 内置供应商被注册（写了 `baseUrl` 或 `models`）时，显示名不再从 pi 的 `DeepSeek` 退化成 id `deepseek`
  ——pi 的 `name` 取值里扩展层优先级最高，只在显式命名时才提交该字段。
- 带 `models` 的内置供应商不再因 `baseUrl` 为空而保存失败：空值不再提交（契约里它是可选的），
  内置卡片会提示「模型清单已被自定义」并提供「恢复默认」回到跟随 pi 的状态。
- 连通性测试改用表单里的 `baseUrl`：此前用的是加载时的快照，改完地址仍会测旧地址。
- `models/refresh` 与启动都会校验配置能否落地：refresh 返回 400 并说明原因，启动打一条告警但不阻断
  （此前手改 config.json 留下的坏条目被静默忽略，只在下次保存时才暴露）。
- 修复整体替换 providers 时 `defaultModel` 变成悬空引用：patch 未显式给出 `defaultModel` 时，
  若旧值指向的 provider 已被替换掉，清空并回落到「第一个可用模型」，避免保存成功但运行时不可用。
- 修复 `models/list` 的 `available` 恒为 `false`：`ModelRuntime.create({ refreshOnCreate: false })` 后从未刷新鉴权快照，
  `hasConfiguredAuth()` 一直是空集；改为按 provider 注入 apiKey 时会同步该 provider 的鉴权状态。
- 新会话发送首条消息后不再有「无加载反馈」的空窗：发送瞬间即进入 pending 态，
  消息区尾部立刻显示「思考中…」，直到首个生成事件或收尾、出错时消除。
- 首轮回答完成前刷新不再丢失会话：当前选中会话同步到 URL（`?session=`），刷新后据此恢复；
  在途草稿会话也会出现在列表里，`messages/list` 改读活跃会话的内存条目，对话区不再空白。
- 输入区发送后不再残留文本：Tiptap 编辑器不受控，此前清空草稿不会重置编辑器内容，
  导致「发出去的消息还在输入框里、再次回车会重复发送」；改为按草稿变化同步重置编辑器，
  且不会因打字触发重挂载（`composer.tsx`）。
- 历史里只有引用、没有正文的用户消息（单独发一个 `@`、或 `/skill:name` 不带参数）不再原样显示
  `<context>` / `<skill>` 展开块：chip 解析允许展开块位于消息末尾（`message-chips.ts`）。
- 草稿态 `/` 菜单改用真实工作目录取命令与技能：此前传的是展示名（如「助理区」），
  会从错误目录解析项目级资源（`composer.tsx`）。
- 切换会话时编辑器不再短暂沿用上一个会话的文档：外部填充记下所属 `editorKey`，
  仅在该键匹配时作为初始文档（`composer.tsx`）。
- 附件仍在上传时按发送会漏掉该附件、且上传完成后又回填进已清空的草稿：上传在途时禁用发送，
  并让 `submit` 以同步计数兜底（`use-composer-attachments.ts`、`composer.tsx`）。
- 非图片附件在历史里直接把内部引用行 `[附件: name (id: …)]` 显示给用户：改为还原成可下载的
  文件 chip，与发送瞬间的乐观视图一致（`message-chips.ts`、`message-item.tsx`）。
- `POST /attachments` 在读完整个请求体之后才判体积上限，超大上传会先被完整缓冲：改为先按
  `content-length` 拒绝，再在读完后兜底（`routes/attachments/index.ts`）。
- 附件过期清理的 DELETE 补上 `referenced_at IS NULL` 条件并只看真正删掉的行，避免与
  `markReferenced` 竞态时误删刚转永久的附件与其文件（`attachment-repository.ts`）。
- 附件转永久的时机改到会话装配成功之后：未配模型等装配失败时不再留下永不清理的永久附件
  （`run.ts`）。

- **`$APP_HOME` 落在 cwd 祖先链上时被当成项目配置目录**：未绑定项目的会话 cwd 就在 `$APP_HOME/workspace/<id>` 下，
  而 `$APP_HOME` 本身就是 `.<slug>` 形态，于是它的父层目录会把 `$APP_HOME` 再认成一份「项目档」——
  技能 / 命令 / 角色的来源标注与同名优先级随之出错（开发布局 `.tmp/.ucode` 下必现）。
  现在解析项目配置目录与资产目录时排除 `$APP_HOME` 自身，并对同一目录去重。
