# 中继（hub）

中继让**本机服务在没有公网地址的情况下也能被访问**：UCode 主动向中继建立一条出站长连接，
中继把公网来的请求从这条连接回灌给本机服务。方案与阶段见 [`plans/hub.md`](../plans/hub.md)，
隧道协议与 ingress 的实现细节见 [`hub/docs/tunnel.md`](../hub/docs/tunnel.md)（两者面向开发，本文面向使用者）。

## 拓扑

```
app / 其他客户端 ──Bearer <中继会话>──▶ 中继 ingress（按 Host 认设备）
                                          │  ① 建流
                                          ▼
                                     隧道（WSS，UCode 主动出站）
                                          │  ② 补本机 serviceToken 后转发
                                          ▼
                                     UCode 服务层（同一套 /api/v1 + 事件流）
```

- **中继不经手 UCode 的鉴权**：`serviceToken` 由 UCode 侧自己注入，中继只知道请求来自哪台设备。
- **进来的调用与本地调用完全一致**：同一套接口、同一套鉴权，只多一个来源标记。
- **中继不是单点**：中继不可达时本机照常干活，只是外面访问不进来。

## 怎么接入

1. **拿到中继地址与账号**：地址由部署方给出（B 端交付可以预置在 `@ucode/brand` 的 `deployment.hubUrl`，
   本机填过之后以本机那份为准）；账号是你在中继上的管理端或客户端账号。
2. **在设置里登录**：设置 → 服务 → **中继**，填地址（已预置可留空）与账号密码，点登录。一次登录同时完成三件事：
   换到登录令牌、**把本机登记成一台设备**（同名设备重复登记只是轮换设备令牌）、把配置写回本机。
3. **隧道自动保活**：配置齐备后服务会自己向中继建立隧道，登录态与隧道状态在同一个页面可见——
   登录账号、设备标识（设备 id 与设备名）、隧道是否连着、本次上线时刻、最近一次失败原因与重连次数。
4. **退出登录**：清掉本机设备绑定与登录凭证并断开隧道，同时尽力吊销中继上的那台设备
   （中继不可达时只记日志，可在中继后台手工吊销）；**地址保留**（它是部署项，不是登录态）。
5. **从浏览器打开本机界面**：在中继的「我的设备」里点这台设备的「打开」，就经隧道直接进入它的 UCode
   （单域名下走 `/d/<设备 id>/`，同源加载，不需要另外登录中继）。离线时中继直接回 502，入口不给。

服务重启后按已存的配置自动重连，不需要重新登录；设备令牌被中继吊销（或丢失）时隧道会停止重连，
重新登录一次即可。

## 把中继模型端点用起来

中继除了转发 UCode 的接口，还提供一组 **OpenAI 兼容的模型端点**：对话与模型清单都由中继用它配好的
厂商转发，厂商密钥不下发到本机。把它当一台普通供应商用，只需让本机的 provider 指向中继：

| 项 | 取值 |
| --- | --- |
| 对话端点 | `POST <中继地址>/v1/chat/completions` |
| 模型清单 | `GET <中继地址>/v1/models` |
| provider `baseUrl` | `<中继地址>/v1` |
| provider `apiKey` | **设备令牌**（`deviceToken`），不是登录令牌 |

**为什么用设备令牌当 apiKey**：中继按「调用方身份」鉴权并记账，设备令牌让用量归到本机所属账号 +
本设备（登录令牌是 `hub` 会话 JWT，用完即弃、会被登出作废）。设备令牌在本机只存于
`service.json`（0600），中继侧只存它的哈希；登出会把它清掉，届时这条 provider 也会随之失效。

### 一键添加

设置 → 服务 → **中继** → 已接入视图里的「模型端点」一节，点「添加为中继供应商」：服务会现拉
`GET <中继地址>/v1/models`，按清单写入一条 provider——
id 固定 `relay`、名称「中继」、`baseUrl` 为中继的 `/v1`、`apiKey` 为设备令牌，
模型能力（思考 / 读图 / 上下文窗口）按模型 id 与清单元数据推断。写入后可在**模型设置**里选它的模型。

- **幂等**：同一个 id，重复点只会刷新模型清单，不会多出第二条供应商；
- **同 id 被占用**：`relay` 这个 id 已被你配成别的端点时会**覆盖**它，界面在成功提示里说明「已覆盖同 id 的供应商」；
- **清单拿不到就不写**：中继不可达、设备令牌不被接受、中继后台没配厂商（清单为空）都会带着中文原因失败，
  不写占位模型——写一条不能用的配置比报错更难排查；
- **不换默认模型**：写入不会改动 `defaultModel`，要不要用它由你在模型设置里决定。

### 手填

不想用一键入口（或要写进另一份配置）时，在模型设置里手动加一条供应商：`baseUrl` 与 `apiKey` 按上表，
模型 id 从 `GET <中继地址>/v1/models` 的清单里挑（`curl -H "Authorization: Bearer <设备令牌>" <中继地址>/v1/models`）。

### 限制与计费

- **只有对话补全**：`/v1/models` 与 `/v1/chat/completions` 两个端点，embeddings / images 等面未提供；
- **按调用方限流**：设备令牌按设备限（对话每分钟 60 次、清单 120 次），超限回 429；
- **用量记在中继侧**：每次调用落一行 `model_usage`，归到调用账号（+ 设备），本机的用量统计看不到这部分；
  写成本机 provider 的模型 `cost` 一律为 0，不做本地成本换算。端点形态、转发与上游超时口径、用量字段见
  [`hub/docs/model-endpoint.md`](../hub/docs/model-endpoint.md)。

## 隧道与 ingress 的行为与限制

| 项 | 行为 |
| --- | --- |
| 连接方向 | 只出站（WSS，`GET /api/v1/tunnel`）；本机不需要开端口、不需要公网 IP |
| 握手凭证 | 每次建连先调中继的 `POST /api/v1/devices/tunnel-ticket`，用长期设备令牌换一张 5 分钟有效的票据，隧道只带票据。中继签票时判「设备在册且未吊销」，握手只验签——所以设备令牌不出现在隧道握手里，吊销在分钟级生效 |
| 地址与端口 | 由中继地址决定（`http` → `ws` / `https` → `wss`，主机、端口与路径前缀都照搬），常见部署就是 443 |
| 同一设备的连接 | 一条：新连接上线即接管旧的，旧连接上在飞的请求按失败收尾 |
| 心跳 | 中继每 30 秒发 `ping`、90 秒内收不到 `pong` 即断开；判死只在中继那一侧 |
| 重连 | 指数退避（1 秒起、封顶 30 秒、±20% 抖动）。只有**凭据失效**（升级被回 401/403，或握手被 `device_unauthorized`）与**协议不兼容**（`protocol_mismatch`）才停止重连并提示重新登录；被新连接接管等其余原因照常重连 |
| 承载的接口 | 与本地一致：`/api/v1/*` 全套，含长连接的**事件流**（SSE）与**工作台终端 / 浏览器面板的 WebSocket**（路径寻址）。单请求体 30MB 级别的附件上传也走得通 |
| **WebSocket 升级** | 支持（协议 v3）：路径寻址（`/d/<设备 id>/…`）下的升级由 hub 终结后经隧道双向转发字节，关闭码原样带回——工作台终端与内置浏览器面板都能用。子域寻址暂不支持（回 501） |
| 单隧道并发 | 64 条流（升级流长期占一条），**只由中继侧判定**：超限回 429（`tunnel_busy`）；单帧载荷上限 1MB（大 body 自动分帧）。路径过长 414、请求头过大 431 |
| 公网寻址 | 两种等价形态：`/d/<设备 id>/`（中继自己的域名下，不必配泛域名）与 `<设备 id>.<中继的 ingress 父域>`（配了父域才启用）。两种地址都由中继给出，**UCode 不知道也不拼** |
| 来源标记 | 经中继到达的请求带 `x-hub-source` / `x-hub-device` / `x-hub-client`，只进请求日志与统计，不参与鉴权 |
| 按路径挂载 | 中继把设备界面挂在 `/d/<设备 id>/` 下时另带 `x-hub-base-path`：UCode 据此改写 `index.html` 的 `<base href>`，让相对资源落在前缀里 |
| 凭证模型 | 中继**不转发访问者的凭证**（`cookie` / `authorization` / `host` 与逐跳头一律剥掉），UCode 只认本机 `serviceToken`——由中继客户端在转发时补上，中继侧不持有 |
| 中继地址带路径 | 中继挂在反代的子路径下时，登录 / 设备接口、模型端点、内置资产清单与隧道都按同一份前缀拼路径 |
| 设备离线 | 中继直接回 502（`device_offline`）并**不排队**；UCode 重连上后自然恢复 |
| 断线表现 | 公网侧看到连接中断 / 502；UCode 侧按上面的退避重连。已建立的事件流会断，客户端自行重连即可 |

部署侧（子域、泛域名证书、反代关闭缓冲、拉长长连接的读超时）由中继的部署文档负责，不在本机设置范围内。

## 安全边界

**经中继到达 UCode 的请求等同本机 owner**——可以读文件、可以跑 `bash`。因此：

- 唯一的门在中继入口：它必须只放行你自己的账号，且只放行属于该账号的设备；
- 登录密码与设备令牌都落在 `$APP_HOME/app/service.json`（与 `serviceToken` 同一份 0600 文件），
  中继侧只存设备令牌的哈希；
- 不要把 UCode 服务直接暴露到公网或不可信网络——引入中继不等于放开监听地址。

## 接口

| 方法 + 路径 | 作用 |
| --- | --- |
| `GET /api/v1/hub/status` | 接入状态：地址 / 账号 / 设备标识 / 隧道运行态 |
| `POST /api/v1/hub/login` | 登录中继并登记本机设备（`url` 可省，省略即用本机已存地址） |
| `POST /api/v1/hub/logout` | 退出中继：清绑定与凭证、断开隧道、尽力吊销中继侧设备（保留地址） |
| `POST /api/v1/hub/provider` | 把中继的模型端点写成本机 provider（固定 id `relay`，清单现拉，幂等） |

四条都需要认证（走常规 `Authorization: Bearer` / 会话 Cookie），字段与响应结构见
[`api-reference.md`](./api-reference.md) 的「中继」一节。失败原因由错误码区分：`hub_not_configured`
（没地址）、`hub_not_bound`（本机没有设备令牌）、`hub_models_empty`（中继没配厂商）、
`hub_unreachable`（连不上）、`hub_login_failed`（登录或设备令牌不被接受）、`hub_register_failed`
（中继拒绝或响应认不出）、`rate_limited`（被中继限流），中文明细随 `params.reason` 下发。
