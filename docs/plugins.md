# 插件

插件把技能、命令、角色、钩子与 MCP 服务器打包成一个可启停、可分发、可升级的单元。
一个按 Claude Code 或 ZCode 规范写的插件包，放进这里就能用；写自己的插件见
[plugin-authoring.md](./plugin-authoring.md)。

## 安装与启停

设置 → 插件：

- **安装**：选来源（本地目录 / 压缩包链接 / npm 包 / GitHub 仓库 / Git 仓库）填地址即可。
  本地目录来源**不复制内容**，改完源文件点「重拉」就生效；其余来源复制进
  `$APP_HOME/plugins/cache/<市场>/<插件>/<版本>`。
- **启停**：停用后它的技能、命令、角色即刻退出会话装配与 `/` 菜单。
- **卸载**：默认只移除登记；勾「清理缓存」会一并删掉安装副本与插件数据目录。
  **本地目录来源的内容永远不会被删**——那是你自己的目录。
- **更新**：点「重拉」按来源重新拉一次。刷新插件市场时顺带检查更新，有变化的插件会标
  「来源已变更，可重拉」。

安装或启停插件后，**正在进行的会话会按新的装配重装**（下一次访问时），
但正在等你批准或等计划确认的会话会先让这一轮走完。

## 市场

市场是一份插件清单（`marketplace.json`）。本轮支持：

| 来源 | 说明 |
| --- | --- |
| 本地目录 | 指向含清单的目录；条目里的相对路径相对它解析 |
| url | 清单直链；用 `ETag` / `Last-Modified` 做条件请求，内容没变就不重复下载 |
| git / github | 浅克隆清单仓；清单可在 `.<slug>-plugin` / `.zcode-plugin` / `.claude-plugin` 下或仓根 |

随包内置两个市场，都**不是强依赖**（GitHub 不可达时刷新失败只记在状态里，不弹错误）：

| 市场 | 来源 | 代码类组件（hooks / 扩展 / bin） |
| --- | --- | --- |
| `<slug>-plugins-official` | 我们自己的官方市场（git 仓，仓里放 `marketplace.json` 与插件目录） | 注入 |
| `claude-plugins-official` | Claude Code 官方市场（git 仓） | **不注入**——它是别人的官方市场，按第三方档处理（技能 / 命令 / MCP 照常可用） |

「内置」只表示开箱就有、刷新失败不弹错；**是否注入执行类组件看市场是谁的**，不看是否内置。

两个都可以删（删除只移除登记，不动已有缓存），删过的内置市场不会被重新加回来；
升级后新增的内置市场会在下次启动时自动并入现有状态。

## 安全边界

插件跑起来就是你的权限，所以有三条明确的取舍：

1. **执行类组件按来源门控**：随包与本地登记的插件的 `hooks/`、`extensions/`、`bin/` 会注入运行时；
   来自第三方市场的**只解析出诊断、不注入**。界面上会直接写明哪些组件没有生效。
   **MCP 服务器不在这条门控里**：它会独立起进程、不是「在你的会话里跑代码」，
   所以第三方市场的 `.mcp.json` 同样生效（见 `plans/plugins.md` 第五章的取舍表）——
   装第三方市场的插件前请自己看一遍它的 MCP 配置。
2. **hook 只能收紧**：`PreToolUse` 的阻断与权限的 `deny` 取并集，插件无法放宽权限。
3. **审查工具**：用内置技能 `/skill:plugin-review` 扫一遍清单、钩子命令、`bin/`、MCP 配置与扩展的
   调用面，它会按「阻断 / 警告 / 提示」给结论。

已知边界：

- 第三方市场的钩子 / 扩展 / bin 不生效（见上）；本地目录安装可以完整自测。MCP 与技能不在此列。
- 变量替换只覆盖 hook 命令与 MCP 配置：技能 / 命令 / 角色**正文里的 `${user_config.*}` 不替换**
  （我们不改写磁盘上的文件），装这类插件时设置页会给出提示；`userConfig` 的值同时以
  `<品牌大写>_PLUGIN_OPTION_<KEY>` 进 hook 子进程的环境变量。
- 插件**没有界面贡献能力**：不改界面，只贡献资源与代码。
- 会话装配关闭了 pi 的隐式扩展扫描（`$APP_HOME/harness/extensions`），扩展只能经插件清单进入。
- `url` / `npm` / `git` 来源需要机器上有可用网络与相应命令（`npm` / `git`）；
  代理环境走系统代理设置，产品自身不读 `HTTP_PROXY`。
- 云同步下发的内置资产（技能与提示词）在中继不可达时静默回落到随包版本。
- `SessionStart` 钩子在**所有**会话里都触发（plan / ask 与只读角色一样）；MCP 那条限制只针对 MCP。
- **项目级只能开关、不能装**：插件本体一律装在 `$APP_HOME/plugins/`，
  仓库里的 `<cwd>/.<slug>/plugins.json` 只改「在这个仓库里开不开」，且只对**这台机器上已登记**的插件生效
  （没装过的 id 直接忽略）。个人覆盖写在同目录的 `plugins.local.json`（建议 gitignore），它压过提交的那份。
  覆盖**既能关也能开**：某个仓库可以把你全局启用、又在别处出问题的插件关掉，也可以把你全局关掉的
  重新打开（与 Claude Code 的 `enabledPlugins` 同一口径）——设置页会标明「由本仓库的覆盖文件决定」，
  开关在那个仓库里是灰的，要改就改那份文件。
  团队要分发插件本体就走市场：仓库里放 `<slug>-plugin/marketplace.json` + `plugins/<name>/`，
  成员各自 `marketplace add` 后安装。
- 安装副本按版本共存：换版本 / 同版本重拉时，旧副本改名成 `cache/<市场>/<插件>/.orphaned-<版本>-<时间戳>`，
  写 `.orphaned_at` 标记后保留 **14 天**（正在跑的会话可能还握着旧路径），到期的副本在下次
  安装 / 重拉 / 卸载时被清掉；一个插件都没装时不清扫。要立刻回收空间就卸载时勾「清理缓存」。

## 数据落在哪

```
$APP_HOME/plugins/cache/<市场>/<插件>/<版本>/   # 安装副本（本地目录来源不复制）
$APP_HOME/plugins/marketplaces/<市场>/          # 市场清单缓存 / 克隆副本
$APP_HOME/plugins/data/<插件 id>/               # 插件自己的持久数据，跨版本保留
$APP_HOME/app/plugins.json                      # 登记表与配置（0600）
$APP_HOME/app/builtin/                          # 随包内置资产物化
```
