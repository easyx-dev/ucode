# ucode 中继（方案）

> 状态：**暂缓（2026-10-05）**。中继暂不开发，本文只归档设计；启动前先落地服务化与鉴权
> （见 [`service-and-auth.md`](./service-and-auth.md)）。

中继是一个**切面**——对外提供一组「登录后才可用」的能力（先落地的是模型 API 端点，后续再加别的 API 端点），
登录这一个动作同时完成三件事：认证、把 ucode 与中继绑定、建立通道。之后 app 顺着通道调用 ucode 服务层。
中继不经手 ucode 的鉴权，只多一个来源标记。

本质是「反向隧道代理」：ucode 处在 NAT 后无法接受入站，由 ucode 主动向中继建立出站长连接，
中继把公网请求回灌。不需要 STUN / UPnP / 打洞。

## 形态

```
app/移动端 ──只登中继──▶ [中继] ══隧道══▶ [ucode 中继客户端]
                                              │ 本地 serviceToken + X-Ucode-Source: relay
                                              ▼
                                        ucode 服务层（同一套 /api/v1 + 事件流）
```

## ucode 侧：只加一个中继客户端

职责四件事：

1. **登录中继**：取得账号身份与设备身份，绑定 ucode 与中继。
2. **保活通道**：出站长连接（WSS），断线重连；通道生命周期跟登录会话，**过期后重新登录即可**（自动续期待定）。
3. **转发 + 来源标记**：隧道进来的请求，用本地 `serviceToken` 按原生客户端方式发给服务——**鉴权管线不改**；同时加来源头 `source` / `clientId` / `deviceId`（先全一些，后续再看取舍），只进 `requestLogger` 与统计，不参与鉴权。
4. **可选 provider**：登录后可把中继模型端点作为普通 provider 注入 `ModelRuntime`。**是否唯一 / 强制看配置，默认不强制**（几个环境变量的事）。

## 关键性质

- **app 只登中继**：ucode 不接触 app 的登录，不需要断言 / 角色 / scope。
- **中继进来的调用与本地 app 层调用完全一致**：同一套接口、同一套鉴权，仅多一个来源头。
- **硬约束**：通道必须能承载 SSE（事件流为长连接流式），中继侧不得缓冲、不得给长连接设请求超时；公网路由用子域以隔离 origin（Cookie / 会话）。
- **降级**：中继不可达时本地仍能用本地 provider 正常干活，中继不是单点。

## 信任推论（必记）

「app 只登中继」+「中继进来的请求等同本地调用 = owner 身份」相加 ⇒ **任何经中继到达 ucode 的请求都是全权身份（可跑 `bash`）**。安全责任完全落在中继入口：中继必须只放行你自己的 app / 账号。角色体系暂缓可以，但将来做多人共享时这条是前提。

## 现在要留的口子（小改动）

1. **鉴权与 ingress 无关**：配对码 / 登录只假设「浏览器能到达服务」，不假设本机还是 LAN（已成立）。
2. **来源头进日志**：`requestLogger` 记录 `source` / `clientId` / `deviceId`，供统计；不参与鉴权。
3. **中继地址并入 B 端定制入口**：`@ucode/brand` 扩为「品牌 + 部署」（relayUrl / edition / 模型端点地址），B 端交付仍只改一处。
4. **配置预置可覆盖 provider**：本地 `config.json` 仍是模型配置唯一事实源，中继登录只是**可选注入**一个 provider。
5. **通道承载 SSE 的约束**写进契约与文档。
