# 工作台面板的布局形态（两栏 + 常驻两标签）

> 状态：**已实现**。数据与接口见 [`workbench-panel.md`](./workbench-panel.md)，视觉取值见
> `DESIGN.md`「分栏」与「面板内部」。本次只改**版式与信息架构**，不动 `fs` / `git` 契约。

## 形态

```
┌───────────────────────────────────────────────────────────────┐
│ ▤   改动 | 文件                                     [▯ 收起]  │ 标签条（两个常驻）
├───────────────┬───────────────────────────────────────────────┤
│ 改动 │ 历史   │                                               │
│ v0 ↑7         │                                               │
│ ▾ packages 31 │        （右列：diff / 提交详情 / 预览）        │
│    M a.ts +2  │                                               │
│ ▸ docs     4  │                                               │
└───────────────┴───────────────────────────────────────────────┘
    左列 = 树面板（可整列关掉、可拖宽）        右列 = 内容
```

两个标签**常驻、不可关闭**；左列（树面板）与右列（内容）的内容都随标签切换：

| 标签 | 左列 | 右列 |
| --- | --- | --- |
| 改动 | 顶部「改动 / 历史」切换；改动视图是**按目录折层的变更树**（目录行带文件数，文件行带状态与增删），历史视图是提交列表 | 所选文件的**改动前后 diff**（结构化 hunk + 双侧行号）；选了提交则显示提交元信息与改动文件，点其中的文件看该提交的 diff；未选时给空态 |
| 文件 | 项目目录树（根名 + 筛选 + 刷新） | 所选文件的预览（工具条：markdown 的预览 / 源码、文件大小、重读）；未选时给「打开文件」空态 |

最左的图标是**树面板开关**，与「改动 / 文件」同排；最右是收起面板。

## 为什么这样

**两个常驻标签比「审查 + 每个文件一个标签」更贴合这里的用法。** 面板是「左侧挑、右侧看」的两栏工具，
标签表达的是**看什么类型的对象**（改动的 diff / 项目里的文件），而不是打开了哪几份文档；
一份文档一个标签的模型会让人不断关标签，也把左列的内容（树）和标签的关系搞乱。

**左列随标签切换，而不是各标签带自己的左列。** 两种左列（变更树、项目树）都是「层级 + 点一下看右边」，
位置与宽度共用一份，切标签时视觉不跳；也复用同一处分栏与持久化。

**改动的左列折成目录树。** 大改动集里按目录收拢比一长条平铺更好找；目录行给出所属文件数，
默认全展开（改动集通常不大，一眼看到文件比逐层点开有用），点目录可折叠。树的构造是纯函数
（`lib/git-tree.ts`，带单测），排序与服务端 `fs/list` 同口径（目录在前、各自 `localeCompare`）。

**右列是结果、左列是入口。** 因此选择状态（哪个变更 / 哪个提交 / 提交里的哪个文件）在面板这一层
用 `hooks/use-git-review.ts` 持有并交给左右两半，右列自带返回（从 diff 退回提交详情或空态）。

## 边界

- 树面板关掉后内容占满；树面板宽度按栏记像素（`<slug>-panels-file-panels`）
- 改动标签的选中项与「打开的提交」在切换视图时清空（diff 与提交详情只属于原视图）
- 文件标签的预览目标由布局持有，切走再切回仍保留
- 没有工作目录（助理会话）时：两列都给「当前没有工作目录」占位
- 变更树单层不设上限（改动条目本身已由服务端限制在 1000 条内）；项目树单层最多渲染 200 项，筛选最多 100 条
